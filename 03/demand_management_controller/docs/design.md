## 1. 引言

### 1.1 目的

本文档详细描述了工商业储能EMS中**需量管理控制器**的设计方案，包括控制算法、软件结构、接口定义、参数配置、异常处理及测试方法。本文档是开发人员进行编码、测试和集成的基础依据。

### 1.2 范围

本文档适用于储能EMS L2层实时闭环控制器中的需量管理模块。该模块运行于实时控制平台（工控机或嵌入式设备），以100ms控制周期运行，负责在满足安全约束的前提下，通过动态调节储能放电功率，控制关口需量不超过用户设定目标值。

### 1.3 术语定义

| 术语 | 定义 |
| :--- | :--- |
| 需量（Demand） | 在滚动时间窗口（通常15分钟）内关口有功功率的平均值，是电费结算中基本电费的计费依据。窗口随时间滑动。 |
| 关口电表 | 安装在电网与用户产权分界处，用于计量交换功率和电量的电能表。 |
| PCS | 储能变流器，负责电池与电网之间的双向功率变换。 |
| BMS | 电池管理系统，提供电池状态及安全约束。 |
| 需量管理 | 通过控制储能放电来削减负荷尖峰，避免关口需量超过设定目标。 |
| 预测窗口算法 | 基于当前滚动窗口平均功率和最老样本，预测允许的瞬时功率上限（cap），从而反推当前允许最大功率的控制方法。 |

## 3. 总体设计

### 3.1 模块划分

需量管理控制器作为L2层的一个独立模块，与防逆流控制器、光伏平抑控制器并列。其输出进入策略合并器，与其它策略输出进行仲裁，最终生成PCS功率指令。

```
┌───────────────┐
│ 关口电表      │──────> P_grid, P_avg_cur, t_elapsed
└───────────────┘
         │
         ▼
┌─────────────────────┐
│  需量管理控制器     │
│  - 预测窗口算法     │
│  - 死区/迟滞        │
│  - 速率限制         │
│  - 安全约束处理     │
└─────────┬───────────┘
          │ P_demand_req
          ▼
┌─────────────────────┐
│  策略合并器         │
│  （与防逆流等合并） │
└─────────────────────┘
          │ 最终P_bat_cmd
          ▼
┌─────────────────────┐
│  PCS指令生成        │
└─────────────────────┘
```

### 3.2 运行状态

控制器内部维护以下状态：

- **正常调节**：实时计算放电功率需求。
- **死区保持**：误差在死区范围内，输出保持上一周期值，不更新积分（本控制器无积分项，但保留输出不变）。
- **禁止放电**：收到 `discharge_enabled=false` 时，输出置零。
- **通信异常**：关口电表数据无效，输出置零并告警。

## 4. 详细设计

### 4.1 控制算法：滑动窗口预测法

#### 4.1.1 数学推导（滑动窗口，2026-08 修订）

需量窗口为**滑动窗口**：任意时刻窗口覆盖最近 `T_window`（典型 900s）的关口功率，窗口平均为最近 `N = round(T_window/Ts)` 个 `P_grid` 样本的平均值。

设本拍样本入窗前窗口平均功率为 `A`、最老样本为 `P_old`。本拍 `P_grid` 入窗后最老样本滚出，窗口能量变为 `E' = N·A − P_old + P_grid`。要求滚动窗口平均不超过目标值 `D_target`（即 `E' ≤ N·D_target`）：

```
P_grid ≤ P_old + N·(D_target − A)
```

故**允许的瞬时关口功率上限**为：

```
cap = P_old + N·(D_target − A)
```

所需放电功率由**窗口平均误差的 PI 控制**给出。`cap` 公式给出了"允许瞬时功率"的目标概念，但直接以 `P_req = max(0, P_grid − cap)` 实施会在目标附近产生通断振荡（见下方方案对比），故放电采用对平均误差的 PI：

```
e = A − D_target
P_demand_req = clamp(Kp_avg·e + Ki·Ts·Σe, 0, P_dis_max)
```

> 注：`cap` 为**理论中间量**（用于解释允许瞬时功率的目标概念），实际控制由 PI 实施；实现中不计算、不对外输出/记录该值。

**窗口未满（启动阶段）**：缓存样本数 `n < N` 时无最老样本滚出，要求新样本入窗后部分窗口平均不越限：

```
cap = (n+1)·D_target − n·A
```

**稳态分析**：PI 的积分项在稳态维持放电基值（`P_int = P_demand_req = P_load − D_target`），比例项消除平均误差，窗口平均**精确收敛到 `D_target`**（实测长时需量稳态 `A=250.000`、`P_req=100`、`P_grid=200`）。相比纯比例/`cap` 直接实施，PI 消除了稳态偏差，并把窗口历史样本滚出/滚入导致的慢速通断（游猎）压缩到最小。

**关于放电公式的选择（2026-08 修订）**：滑动窗口目标附近，各方案长期行为实测对比如下：

| 方案 | 长期行为 |
| :--- | :--- |
| `cap` 直接实施 `max(0, P_grid−cap)` | 慢速通断（P_req 0↔100kW，周期≈窗口时长） |
| `cap` 重构原始负载 `max(0, P_grid+P_req_prev−cap)` | 高频锯齿振荡（P_req 50~150kW）——最差，不采用 |
| 纯比例 `max(0, Kp_avg·(A−D_target))` | 慢速通断（同上） |
| **PI（本方案）** | 放电期稳态 `P_req` 恒定、`A=D_target` 精确；仅窗口结构切换时短暂空闲（A∈[249,250.5]，±0.2%） |

游猎的根本原因：滑动窗口历史样本（如瞬态高负载留下的"能量债务"）随窗口滚动进出，窗口平均随之漂移，任何只响应窗口平均的反馈控制器都会在目标附近慢速切换。PI 的积分项维持放电基值，将 A 的偏差压缩到 ±0.2%；真实 900s 窗口下，游猎周期约等于窗口时长（约 15 分钟一次放电周期），可接受。

**与原固定窗口公式的关系**：早期固定窗口公式 `P_remain_allow=(D_target·T_window−P_avg_cur·t_elapsed)/t_remain` 中 `t_remain→0` 时分母发散，**不适用于滑动窗口**，已由上述 `cap` 公式替代。

#### 4.1.2 特殊情况处理（滑动窗口）

- **窗口未满（启动阶段）**：使用未满窗 `cap` 公式，保证部分窗口平均不越限；窗口填满后自动切换满窗公式。
- **已越限**：若 `A > D_target`，说明当前滚动窗口平均已超目标，控制器置 `alarm` 告警。放电幅值由 PI 控制连续给出——越限越深放电越大，显著越限时比例项饱和到 `P_dis_max`。若负载超过 `D_target + P_dis_max`，即使满功率放电也无法将 `P_grid` 压到目标以下，窗口平均将持续越限并保持告警。
- **输入异常**：`P_grid` 非有限值或通信异常（`comm_fault`）时，输出0并置告警，且无效样本不入窗。
- **响应特性（滑动窗口只控平均、不控瞬时，2026-08 修订）**：`cap` 仅在窗口平均 `A` 逼近 `D_target` 时收紧。负载瞬时越限（`P_grid > D_target`）但滚动平均仍有裕量时，控制器**不会立即放电**——真实 900s 窗口（N=9000）下负载 200→300 约需 7.5 分钟（A 从 200 爬到 250）才触发。这是滑动窗口"按需量（平均）计费"的本意：瞬时尖峰不影响计费，仅滚动平均越限需要干预。PR-03"响应<200ms"指**检测到越限趋势后**的动作时间，而非负载突增后的首次动作时间。若需要瞬时限流，应在策略合并层叠加瞬时上限（本控制器不实现）。

### 4.2 防频繁启停

放电采用 PI 连续输出，无需输出死区：`P_grid` 低于目标（`A ≤ D_target`）时由 `max(0, ·)` 自然输出 0，冲击由 4.3 的功率变化率限制抑制。早期"输出死区"（`P_req < deadband → 0`）会破坏比例响应的连续性，在均衡点附近造成通断振荡，已移除。

### 4.3 功率变化率限制

储能放电功率的变化率不能超过 `dP_max`（kW/s）。在每个控制周期内，输出变化量限制为：

$$
\Delta P_{max} = dP_{max} \times Ts
$$

对上坡（增加放电）实施限制，下坡（减少放电）允许快速下降以避免过度放电。若需对称限制，可同时限制下坡。

### 4.4 安全约束集成

- 从A组获取 `P_dis_max` 和 `discharge_enabled`。
- 当 `discharge_enabled = false` 时，输出强制为0。
- 当 `P_dis_max <= 0` 时，输出强制为0。
- 输出始终被钳位在 `[0, P_dis_max]`。

### 4.6 状态机设计

```
        ┌──────────────┐
        │  正常调节    │
        └──────┬───────┘
               │
   ┌───────────┼───────────┐
   │           │           │
   ▼           ▼           ▼
┌──────┐  ┌──────┐  ┌──────────┐
│死区  │  │禁止  │  │通信异常  │
│保持  │  │放电  │  │(输出0)   │
└──┬───┘  └──┬───┘  └────┬─────┘
   │         │           │
   └─────────┴───────────┘
             │
             ▼
           (返回到正常调节)
```

- **正常调节**：PI 实时计算放电功率。
- **目标附近**：`A ≤ D_target` 时 PI 输出为 0（无放电）；`A > D_target` 时按平均误差连续放电。
- **禁止放电**：`discharge_enabled=false` 时，输出强制为0，一旦恢复允许且满足条件则回到正常调节。
- **通信异常**：关口电表数据无效（如超时、品质位无效），输出为0，告警，直到通信恢复。

### 4.7 伪代码

```python
class DemandController:
    def __init__(self, config):
        self.T_window = config['T_window']
        self.D_target = config['D_target']
        self.dP_max = config['dP_max']
        self.Kp_avg = config['Kp_avg']
        self.Ki = config['Ki']
        self.integral_max = config['integral_max']
        self.Ts = config['Ts']
        self.N = round(self.T_window / self.Ts)   # 滑动窗口样本数
        self.window = collections.deque(maxlen=self.N)  # 窗口缓存
        self.integral = 0.0
        self.last_output = 0.0
        self.active = False
        self.alarm = False

    def update(self, input):
        # 通信异常 / 输入非法：不更新窗口，输出0并置告警
        if input.comm_fault or not math.isfinite(input.P_grid) or input.P_grid < 0:
            self.last_output = 0.0
            self.active = False
            self.alarm = True
            return 0.0

        # 入窗前窗口平均
        n = len(self.window)
        A = (sum(self.window) / n) if n > 0 else 0.0

        # 本拍样本入窗（有效计量数据无论输出是否被安全约束都记录）
        self.window.append(input.P_grid)

        # 已越限告警（放电幅值由 PI 连续给出，显著越限比例项饱和到 P_dis_max）
        self.alarm = (A > self.D_target)

        # 安全约束（BMS禁止放电 / 最大放电功率为0）：输出0
        if not input.discharge_enabled or input.P_dis_max <= 0:
            self.last_output = 0.0
            self.active = False
            return 0.0

        # 对窗口平均误差的 PI 控制（积分项维持放电基值，抑制窗口历史导致的游猎）
        e = A - self.D_target
        P_prop = self.Kp_avg * e
        P_int  = self.Ki * self.Ts * self.integral
        output = min(max(P_prop + P_int, 0.0), input.P_dis_max)

        # 遇限削弱积分（上限/下限饱和时停止累加；积分项单向 >=0 硬限幅）
        sat_high = (output >= input.P_dis_max) and (e > 0)
        sat_low  = (output <= 0.0) and (e < 0)
        if not sat_high and not sat_low:
            self.integral += e
        self.integral = min(self.integral_max, max(0.0, self.integral))

        # 功率变化率限制（上坡限速；下坡允许快速退出）
        max_change = self.dP_max * self.Ts
        if output > self.last_output + max_change:
            output = self.last_output + max_change

        self.last_output = output
        self.active = (output > 0.0)
        return output

    def reset(self):
        self.window.clear()
        self.integral = 0.0
        self.last_output = 0.0
        self.active = False
        self.alarm = False
```

## 5. 异常处理与安全保护

| 异常类型 | 检测方法 | 处理措施 |
| :--- | :--- | :--- |
| 关口电表通信中断 | `comm_fault=true` | 输出置0，置告警；无效样本不入窗（窗口保持最近有效数据） |
| BMS禁止放电 | `discharge_enabled=false` | 输出置0（窗口仍记录实际功率，恢复后尽快拉回窗口平均） |
| 最大放电功率为零 | `P_dis_max<=0` | 输出置0（窗口仍记录实际功率） |
| 输入非法 | `P_grid` 非有限值或为负 | 输出置0，置告警；无效样本不入窗 |
| 已越限 | 窗口平均 `A > D_target` | 置告警；放电幅值由 cap 公式连续给出（显著越限自动饱和到 `P_dis_max`） |
| 计算异常 | 无（cap 公式无除法运算） | — |

## 6. 参数配置与整定

### 6.1 参数列表

| 参数 | 单位 | 默认值 | 范围 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| `T_window` | s | 900 | 固定 | 滑动窗口时长，通常由电表决定 |
| `N` | 个 | round(T_window/Ts) | 派生 | 窗口样本数，控制器内部计算 |
| `D_target` | kW | 250 | 用户设定 | 目标需量上限 |
| `Kp_avg` | kW/kW | 100 | 50~500 | 窗口平均误差比例增益 |
| `Ki` | kW/(kW·s) | 20 | 5~50 | 平均误差积分增益（维持放电基值） |
| `integral_max` | — | 5000 | ≥0 | 积分项上限（放电单向，下界为0） |
| `dP_max` | kW/s | 50 | 10~100 | 功率变化率限制 |
| `Ts` | s | 0.1 | 固定 | 控制周期 |

### 6.2 参数整定建议

- **`Kp_avg`**：决定对平均误差的响应速度与稳态精度。增大加快响应、缩小偏差，过大会引起振荡（须远小于窗口样本数 N）。默认 100 时稳态偏差约 0.2%。
- **`Ki`**：决定积分项建立放电基值的速度。过小积分保持力不足（目标附近游猎明显），过大可能超调；默认 20 可在 10s 内建立 100kW 放电基值。
- **`dP_max`**：根据PCS允许的最大功率爬升速率设定，兼顾响应速度和设备保护。
- **`D_target`**：由用户根据电费结构和历史需量数据设定，通常略低于变压器额定容量。
