# 09/ — 周期 9：多策略组合测试（闭环时序级）

> 依据：`工商业储能EMS调控策略设计方案.md` §7 周期 9
> 目标：**杜绝策略指令冲突、互相覆盖、频繁切换、双向充放电、功率超限**

---

## 1. 这一层到底在测什么

`04/tests/test_arbiter.cpp` 的 T11~T17 已经覆盖了同样的 7 个组合场景，但那是
**单拍仲裁级**：手工构造 `StrategyResult` 列表，调一次 `arbitrate()`，验证区间收敛。

本模块是**闭环时序级**：真实策略 + 真实安全引擎 + 真实状态机 + 真实被控对象
（`PlantModel`，含 PCS 一阶惯性 + 传输延时），连续跑 **12000 拍（1200 s @ 10 Hz）**。

两者的关系不是重复，而是**层次递进**：

| | 04/ T11~T17 | 09/ T91~T97 |
| --- | --- | --- |
| 时间尺度 | 单拍 | 12000 拍时序 |
| 被控对象 | 无（纯仲裁） | `PlantModel`（惯性 + 延时 + 死区） |
| 状态机 | 无 | 真实 FSM（INIT→…→NORMAL/DERATED） |
| 安全层 | 无 | `SafetyEngine` 9 类约束全开 |
| 能暴露的问题 | 区间收敛错误 | 极限环、死锁、滞环失效、执行机构动态 |

**单拍正确 ≠ 时序正确。** 本周期实测证明了这一点：单拍全绿的 7 个场景，在时序上
暴露了 4 个真实缺陷（见 §4）。

## 3. 断言维度（不变量）

### 3.1 硬不变量（**任何**时刻都必须成立）

| 不变量 | 判据 | 为什么与执行机构动态无关 |
| --- | --- | --- |
| 指令逃逸 | `p_cmd ∈ [p_lower, p_upper]` | 这是 EMS 自己声明的权限区间；设备端按 `PermissionRange` 限幅执行（接口规范 §5），越界即"EMS 预期 ≠ 设备执行" |
| 功率超限 | `\|p_cmd\| ≤ min(PCS, BMS)` | 同上 |
| 门控不变量 | 非运行态 `p_cmd ≡ 0` | 状态机契约 |

### 3.2 时序不变量

| 不变量 | 阈值 | 说明 |
| --- | --- | --- |
| 双向充放电 | 指令符号翻转率 ≤ 0.20 /s | 沿用 07/ 工程口径 |
| 频繁切换 | 指令方向反转率 ≤ 1.00 /s | 同上 |

### 3.3 安全不变量（**稳态**）

| 不变量 | 判据 |
| --- | --- |
| 关口越界 | `P_grid ∈ [grid_min_required, grid_max_required]` |
| 变压器越限 | `\|P_grid\| + 0.1·P_load ≤ tr_overload_th · cap · tol` |
| SOC 越界 | `SOC ∈ [soc_min − 1%, soc_max + 1%]` |

**为什么要区分稳态**（`ScenarioConfig::settle_ticks`，默认 50 拍 = 5 s）：

- **门控期**（INIT / SELF_CHECK / READY / FAULT）储能不动作 —— 此时关口越限
  完全由负荷·光伏本身造成，EMS 想动也动不了，不属控制律失效。
- **门控解除后的若干拍**：PCS 受**一阶惯性 + 传输延时**约束，实际功率从 0 爬到
  指令值需要时间。实测：S3 需 ~9 拍，S4 需 ~35 拍（要吸收 250 kW 光伏余电）。
  这段过渡期的越限是执行机构动态，不是策略冲突。

因此判定条件是"连续非门控拍数 > `settle_ticks`"。这不是放宽标准 ——
**硬不变量与时序不变量仍然逐拍判定**，只有依赖被控对象响应的安全不变量
才区分暂态/稳态。

## 4. 本轮修复的 4 个真实缺陷

全部由本模块的时序测试暴露，且全部是**架构级**问题（不是场景参数问题）。

### 缺陷 1：变化率约束的区间从 `as_results()` 逃逸（假区间矛盾）

`ConstraintResult` 声明了 `binds_interval`（变化率约束为 `false`，**不参与区间求交**），
`SafetyEngine::evaluate()` 也按此过滤；但 `ConstraintResult::to_strategy_result()`
这条**出口**把 `p_lower/p_upper` 原样导出给了仲裁器，等于绕过了该规则。

后果：变化率约束的区间是"相对上一拍指令的邻域"（如 `[−20, +20]`），与并网硬区间
（如 `[42, 250]`）求交即得 `42 > 20` → 仲裁器误判**区间矛盾** → 塌缩为 `[0,0]`。

实测：S3 指令逃逸 **3724 拍**、关口越界 3728 拍；S4 逃逸 1016 拍。

**修复**：`to_strategy_result()` 对 `!binds_interval` 的约束导出 `[−1e18, +1e18]`，
与 `evaluate()` 的过滤规则保持一致。

### 缺陷 2：区间同步后可能为空（`p_lower > p_upper`）

`apply()` 用安全区间对仲裁区间做 `max/min` 同步。当仲裁区间与安全区间**互斥**时，
同步结果为空区间 —— 此时**任何** `p_cmd` 都会逃逸。

**修复**：同步后显式检测空区间，以**安全区间权威接管**（安全边界是硬约束）；
仅当安全区间自身也矛盾时才退回 `[0,0]`。

### 缺陷 3：门控时权限区间未同步收成 `[0,0]`

状态机门控把 `p_cmd` 置 0，却把 `p_lower/p_upper` 留在 `[42, 250]`。
这造成"指令 0 却声明允许区间 `[42, 250]`"的矛盾 —— 设备端按 `PermissionRange`
限幅执行时会把 0 **抬到 42**，恰恰违反门控。

**修复**：门控分支同时把权限区间收成 `[0,0]`；`hold_last` 分支同理把区间钉在
保持指令上（单点）。

### 缺陷 4：变压器约束的方向性错误 + 缺乏前馈

两个独立问题：

**(a) 方向性**：原实现把"极端过载"一律处理为**禁放**（`p_upper = 0`）。
但变压器负载看的是关口功率的**绝对值**，而进口方向过载时**放电会降低 `P_grid`**，
恰恰是缓解手段；禁放反而让过载持续（S2 实测越限 3577 拍）。
正确做法是把约束表达为 `P_bat` 的**可行带**：

```
设 base = P_load − P_pv（储能不动作时的关口功率），则 P_grid = base − P_bat
要求 |P_grid| + 0.1·P_load ≤ th·cap
  ⟺ |base − P_bat| ≤ half,  half = th·cap − 0.1·P_load
  ⟺ P_bat ∈ [base − half, base + half]
```

可行带与设备能力**完全错位**时**投影到最近端点**（饱和输出，尽力把负载率压到最低），
而不是制造空区间后放弃输出 0。

**(b) 缺乏前馈**：约束若只看**电表量测**，只能在负载率**已经**越过阈值后才动作；
而 PCS 有传输延时 + 一阶惯性，此刻被控对象已"带着动量"，必然再冲过一段 ——
阈值留多少余量都不够（实测：阈值 0.95 时冲高到 1.014；收到 0.90 仍冲高到 286 kW）。
**修复**：取「量测值」与「上一拍指令落地后的预测值」的**较劣者**参与判定，
约束就能在**指令下发之前**拦住会过载的指令。

同一缺陷也存在于 `04/src/strategies_9.h::TransformerLimitStrategy`（旧实现，
运行时不注册，L0/L1 由 05/ 权威给出），已同步修正。
