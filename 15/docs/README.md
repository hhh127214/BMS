# 15/ 平台层前端 · 运行界面

> 一句话：把 14/ 数据库里的 24 h 仿真结果，变成一屏能看懂、能回放、能下钻的运行态势。

---

## 1. 为什么需要 15/

`14/` 把仿真产物装进了 SQLite 并开了 24 个 REST 接口 —— 但接口是给机器看的。
`15/` 补的是**最后一段**：让人能看见。

三个具体判断：

1. **平台层缺了前端就不是平台层。** 框架 §3.1 的平台层定义是「数据 + 服务 + 界面」。
   只有库和接口，运维人员要自己拼 `curl`，等于没有平台。
2. **仿真结论必须能被"看见"才可信。** `10/` 的净收益 572.01 元、`09/` 的告警分档、
   `07/` 的本拍闭环四个布尔 —— 这些数字在报告里是一行字，在这里是能回放的一天。
3. **界面是接口契约的第一道真实验证。** 24 个接口里有 401/403/404/400 四类负路径，
   写自检能覆盖，但**"页面真的渲染出东西了"**只有点开才知道。

**七个文件、4991 行、零第三方依赖、零打包步骤。**

★ `assets/assembly.js` 是**派生产物，不要手改**：源是
`docs/规划/部件测点映射表.csv`，改了 CSV 请重跑
`python 15/scripts/gen_assembly.py`（`--check` 只比对不写盘）。
它带着 CSV 原值（`src` 字段），`selftest` 的 J 段据此**逐点**比对三列 ——
这是"界面结构没与现场点表脱钩"唯一的自动拦截点。

图表是手写 SVG（`lineChart` / `barChart` / `energyFlow`），不引 ECharts / Chart.js
—— 与 `10/src/sim_report.h` 同一路数：报告和图都不该依赖外部 CDN，
否则断网打不开、版本漂移会让同一份数据画出不同的图。

折线图带**游标联动**（`lineChart` 的 `cursor: true`，hover 显示该时刻各系列数值）；
三张图都能用 `ui.js` 的 `exportSvgPng()` 导成 PNG（纯前端，canvas 序列化，
导出前会把 CSS 变量解析成当前色值内联，避免导出图变黑块）。

## 3. 快速开始

```bat
REM  ① 先确保数据库有数据（14/ 的活）
scripts\import_sim.bat

REM  ② 起服务 + 托管界面
15\scripts\run_ui.bat
REM  浏览器打开 http://127.0.0.1:8765/
```

> **不能双击 `index.html` 打开。**
> 界面要调 24 个 `/api/*`，`file://` 协议下浏览器按跨源直接拦掉，
> 页面会停在"加载失败"。必须由 `14/src/server.py` 托管。

默认账号：

| 账号 | 口令 | 角色 | 能看什么 |
|---|---|---|---|
| `admin` | `admin123` | 管理员 | 全部 **12** 页（含用户与审计） |
| `operator` | `operator123` | 运行员 | **11** 页（能改策略、能下发指令） |
| `viewer` | `viewer123` | 只读 | **11** 页（全部只读） |

（12 = `app.js` 的 `MENU` 项数；唯一带 `minRole: 'admin'` 的是「用户与权限」，故其余两档少 1 页。）

**现场部署前必须改默认口令**（见 `14/docs/README.md` §5）。

## 4. 界面结构（11 页）

| 页面 | 主要数据源 | 关键内容 |
|---|---|---|
| 总览 | `overview` | 4 指标卡 / 640×344 能量流图（等轴测 3D 场景：**实心粗箭头**表达潮流、方向字（停机/用电/充电/购电…）写在箭头杆里，中线是 **3D 汇流柱**且「交流母线」四字竖排；名称挂图案外侧、数值在图案下方） / 本拍闭环 / 安全红线 / 告警分档 / 经济性 |
| 实时监控 | `realtime` + `overview` + `series` | 仿真时标滑块（8640 拍任意回放，**切页再回来停在上次那一拍**）+ 播放 / 设备实时量 / 储能与闭环 / 全天 SOC 走势（游标指当前拍） |
| 历史曲线 | `series` | 7 条曲线多选对照（关口/负荷/光伏/储能实际/指令/权限上下界）+ SOC 专图，采样 48~960 点 |
| 告警中心 | `alarms` + `alarms/summary` | **等级 × 来源 双维筛选**（可任意组合、再点一次取消）/ 两张分类统计表**可点即筛** / 24 h 小时柱状分布（已应用当前筛选） |
| 策略配置 | `strategies` | 9 个策略的开关与参数 + 仲裁优先级 + 下发指令演示 |
| 收益分析 | `economics` + `energy` | 净收益构成 / 节省率 / 日周月对比 |
| 报表系统 | `report` | 日 / 周 / 月三档 + 导出时序与告警 CSV + **打印 / 存为 PDF**（`@media print`） |
| **装配视图** | `realtime` + `assembly.js` | 柜 → 舱 → 部件的**等轴测爆炸图**：4 部位 / 14 部件 / 78 测点；点部件看它的全部测点定义 |
| **一次接线图** | `overview` + `realtime` | 12 节点 / 12 条连接，实线=主电流路径、虚线=辅助挂载（不导电）+ 当前功率 + 9 条连接清单 |
| 设备管理 | `devices` + `realtime` | 台账（额定功率 / 容量分列）+ 当前功率 + 点表口径 |
| 用户与权限 | `users` + `audit` | 用户列表 / 新建用户 / 最近 100 条操作审计（**仅 admin 可见**） |

**★ 装配视图上"多数部件是灰的"是事实，不是没做完。**
14 个部件里**只有 5 个**能取到实时值 —— `/api/realtime` 只返回
`DEV-METER-01 / DEV-PV-01 / DEV-LOAD-01 / DEV-PCS-01 / DEV-BMS-01` 五台设备。
其余 9 个部件的点要走 `13/` 的 Modbus 接入才有数，所以画成**灰的并写「无实时源」**。
把它们涂成"正常"等于谎报现场这个部件在传数据 —— 不报错、界面上什么都看不出来，
正是本项目最忌讳的失效方式。

**★ 一次接线图 ≠ 总览的能量流图。** 能量流是**能流示意**（四节点定死，
回答"电往哪走、走多少"）；接线图是**拓扑事实**（节点来自
`docs/规划/柜体装配视图.md` §2 的 9 条连接，回答"柜里有什么、怎么接的"）。
辅助舱三个部件（消防 / 空调 / 门禁）挂在柜**外**、用虚线 —— 它们不走主电流，
画进主链等于说"电流流过烟感"。

**「实时」= 仿真时标，不是墙上时间。** 8640 拍可以 1 秒看完，也可以逐拍跟踪
—— 这是离线仿真平台该有的形态，接真机后接口与表结构都不用改。

## 5. 前端调用的接口（24 个）

| 类别 | 接口 |
|---|---|
| 认证 | `GET /api/health` · `POST /api/login` · `POST /api/logout` · `GET /api/me` |
| 总览 | `GET /api/overview` |
| 设备 | `GET /api/devices` · `GET /api/devices/{id}` |
| 时序 | `GET /api/realtime` · `GET /api/series` · `GET /api/steps` · `GET /api/commands` |
| 告警 | `GET /api/alarms` · `GET /api/alarms/summary` |
| 策略 | `GET /api/strategies` · `PUT /api/strategies/{id}` |
| 经济 | `GET /api/economics` · `GET /api/energy` · `GET /api/report` |
| 安全 | `GET /api/invariants` |
| 控制 | `POST /api/control/command` |
| 管理 | `GET /api/audit` · `GET /api/users` · `POST /api/users` |
| 导出 | `GET /api/export/{kind}` |

**接口对齐是被自检强制的**：`tests/selftest.js` 会解析 `14/src/api.py` 的 `ROUTES`，
逐条核对前端调用的路径后端是否真有（含 `{id}` 这类参数化路径）。
前端写错一个字母，构建时就红，不用等到点开那个页面。

`/api/energy-flow` 是 `/api/overview` 的语义化别名（同一 handler），前端不单独调
—— 能量流所需的四个功率量已随 `overview` 一次返回，少一次往返。

## 6. 权限与可见性

- 侧栏菜单按角色过滤（`app.js` 的 `MENU[].minRole`），非 admin **看不到**「用户与权限」。
- 直接改 hash（`#/users`）绕不过去：`enterApp()` 会校验目标页是否在可见菜单里，
  不在就落回「总览」。
- **这只挡前面。真正的门在后端**：`14/src/api.py` 的 `ROUTES` 每条都带最低角色，
  越权请求返回 403、未登录返回 401。前端的过滤是体验，不是安全边界。
- 控制指令下发在无真实执行器时**不会假装成功**：接口返回
  `{"accepted": false, "executor": "none", ...}`，界面显示"本次只记录意图并审计"。

## 7. 自检

```bat
15\scripts\run_selftest.bat
```

361 条断言，十六段：

| 段 | 内容 |
|---|---|

| B 接口契约 | 对 `14/src/api.py` 的 `ROUTES` 逐条核对（含参数化路径） |
| C 页面与权限 | 菜单 12 项 ↔ `Pages` 导出 12 个函数一一对应、图标齐备、角色门槛 |
| D 渲染纪律 | 表格/文本走 `textContent`、`innerHTML` 只出现在白名单 4 处、无 `eval`（**扫剥注释后的源码**） |
| E 图表与样式 | 20 个渲染函数 + `fmt` 9 个方法齐备、4 个量测色互不相同、**用到的 CSS 变量全部有定义**、图例/数值钩子齐备 |

| G 能量流改版契约 | 粗箭头是 7 点实心多边形（不再用 `<marker>`）、方向字在杆里、母线 3D + 竖排标签、**菜单小蓝点与顶栏小绿点必须不存在** |

| **I 引擎双模式（run / sim）** | 引擎分段器与切换后重解析、`canWrite` 角色门槛、`LIVE_PAGES` 白名单恰好 8 页 `overview / realtime / curves / alarms / economics / report / structure / wiring`（**`strategies` 不在其中**）、<br>自动刷新定时器清理与 `document.hidden` 让路、`keepScroll` 保滚动位置、实时徽章三态、`onDispose` 契约、<br>启停前 `confirm` + 清空、来源标注读后端 `source_is_model`（不写死）、<br>仿真页 kinds 动态取、轮询清理、删除、典型日回绕与故障窗提示、`openDataset` 先切到 sim |
| **J 装配视图 ← CSV 一致** | 4 部位 / 14 部件 / 78 测点；`src` 集合与 CSV「所属部位」一致；**78 个测点逐行比对「测点名 / 设备点名 / 单位」三列**；仅 5 个部件绑实时设备；生成器存在 |
| **K 报表打印与告警分类** | `@media print` 拆掉了 `overflow`（否则只印第一屏）、操作条 `.no-print`、打印抬头带 `data_note`；<br>告警筛选存 `PREFS`（本页在 `LIVE_PAGES` 里，不存会被 5 s 重刷冲掉）、等级全谱与后端同一份清单、分类表可点；<br>后端 `source` 筛选存在、按全谱补零、走交叉筛选、**不开 `status` 筛选**（假入口） |
| **[M] 一次接线图几何** | **用 vm 把 `ui.js` 装进沙箱真跑一遍 `wiringDiagram()`**，把产出的 SVG 拆成文字盒子与线段两两求交：<br>数字不骑框 / 数字不压文字 / 线不穿框，各 1 条；<br>另加 4 条静态（同列竖连、`safeX` 竖直段避让、辅助母线、label 抬 33 到框外）+ 2 条夹具一致性 |
| **[N] renderPage 静默刷新** | **从 `app.js` 原样抽出 `renderPage` 函数体**，配最小 DOM 桩在 Node 里真跑四条路径：<br>数据未变→一字节不动、数据变了→幕后建树后原子换屏、取数失败→保留上一屏、主动换页→清屏+「加载中…」；<br>并把 `disposers` 的**入界快照 `d0` 记账**逐条钉死（退旧 / 留新 / 都不退，三条路各不相同） |
| **[O] lineChart x 轴刻度** | **在同一个 vm 沙箱里真跑 `lineChart()`**，从产出的 SVG 反解 x 轴刻度盒两两求交：<br>wall 19 字符长标签 / sim `HH:MM` / 跨午夜不误剥 / SOC（170 高）四组全部不重叠；<br>另断言共享日期前缀只画一次、无日期前缀时不凭空画 |
| **[P] 数据未就绪 ≠ 加载失败** | **从 `app.js` 抽出 `renderNotReady` / `switchEngine` / `enterApp` 三个函数体**逐条断言：<br>404 才走空状态、5xx 仍说「加载失败」；空状态里**不出现**以「加载失败」开头的文案，但**必须**显式写明「这不是加载失败」；出路走既有接口（`setEngine` / `liveStart`）且按角色给；<br>★ `setEngine` 全文件只剩 1 处调用（空状态与顶栏共用 `switchEngine`，各写一遍必然漂移）；<br>★ `enterApp` 在隐藏登录框之后必须有 try 兜底（否则错误文案写进看不见的 `#login-err`，用户看到的是空白页） |

★ **M / N / O 三段是本文件里运行时实测的三段**（都通过 `vm` 真跑函数体，不是文本匹配）。
★ **[P] 段本身是文本/正则**（抽函数体后断言"里面必须/不许出现什么"），
  但它守的那条**行为规则在 [N] 段的沙箱里真跑过**：404 + 主动换页 → 画未就绪页；
  404 + 静默刷新 + 已有旧屏 → 保留旧屏；404 + 静默刷新 + 还没有旧屏 → 也画未就绪
  （否则首屏永远停在「加载中…」）。这也是**合并时两边策略冲突的地方**：
  远端 §68 只要"失败就保留上一屏"，我们额外要求"404 ≠ 加载失败"对用户可见 ——
  两条在"静默刷新遇 404"这一点上相反，最终按**有无旧屏**分流。
其余各段是文本 / 正则，能证明"代码里写了某个逻辑"，证明不了"跑起来真的对"——
接线图那次是**几何算错**：label 放在"节点中心 −8"正落在节点名称那一行上；
出线固定"右缘→左缘"在目标位于左侧时绕回、横穿目标框；辅助舱三根折线的竖直段落在主链节点框内。
静默刷新那次是**定时器记账**错（旧屏与新树混在同一个 `disposers` 里：全退会误杀新页、全留会泄漏）。
曲线那次是**刻度数写死**（按 5 字符的 `HH:MM` 调参，换成 19 字符的完整日期时间就必然两两重叠）。
这三类都是静态断言看不见的，只能真跑一遍。

G 段守的是"**改回去了也不会有人发现**"的那类画法约定：老的小三角 marker、
侧边方向徽章、扁平竖条母线、菜单激活态小蓝点、顶栏连通小绿点。少了它，
任何一次重排都可能把它们悄悄带回来。

★ D / G 两段现在都扫**剥掉注释后**的源码（`stripComments`）。
原因是踩过两次：新写的注释里出现 `html:`、`<marker>` 这两个**字面词**，
被静态正则当成真实使用点，报出来的却是"渲染纪律有问题""又用了 marker"
这类吓人的说法 —— 纯误导。正则不认注释，所以先手动剥一层。

**没有 Node 怎么办**：`run_selftest.bat` 会打印 `[SKIP]` 并以 0 退出。
环境缺失不是代码缺陷 —— 但**必须显式喊出来**，否则"静默跳过"与"真的跑过"在输出上不可区分。

## 8. 已知边界

1. **没接真机（真实 PCS / 电表 / 调度）。** 现场量有**两个来源**：`10/` 的 24 h
   离线仿真（默认场景）与 `07/` 现场进程 `--record` 的实时实录（live 场景）——
   但**这两个都不是真机联调**，真硬件从未接过。界面「数据来源」卡片
   把这件事写在脸上 —— 这类事情藏着不说，比说出来的后果严重得多。
2. **界面没有做过浏览器兼容性验证。** 目标是 Chrome / Edge 现代版本
   （用了 `fetch` / `URL` / CSS 变量 / `Array.flatMap`），不保证 IE。
3. **控制下发只有"记录 + 审计"。** 没有真实执行器，也没有接 `13/` 的 Modbus 写通道
   —— 后者属于"接入真介质"，不在本次范围。
4. **图表仍是简版。** 只有折线、柱状和能量流三种；折线图已加**游标联动**
   （hover 显示各系列该时刻数值）与 **PNG 导出**（`ui.js` 的 `exportSvgPng()`），
   但没有缩放、没有区间拖选。够用即可，不追求仪表盘产品的完整度。
5. **登录态在 `localStorage`，12 h 过期。** 没有做刷新 token、没有单点登出。
   口令本身不落 `localStorage`（只存 token），这条有自检守着。
6. **口令暴露面已收窄，但仍有两处要在上现场前处理**：
   - `15/index.html` 的登录页**不再回填口令**（旧版把 `admin / admin123` 预填进输入框、
     并在下方明列三个默认账号 —— 已删除）。演示/测试用的账号改由脚本显式填值：
     `15/tests/e2e_probe.html` 与 `15/tests/screenshot.html` 自己 `.value = ...`，
     **不依赖页面预填**，所以删掉预填不影响端到端验证。
     账号与角色仍记录在本节 §权限（离线文档，不进界面）。
   - **默认口令本身仍在库里**：`admin/admin123`、`operator/operator123`、`viewer/viewer123`
     由 `14/` 的导入器种入 `app_user` 表。上现场前**必须改**
     （见 `14/docs/README.md` §5）。
    - 后端是**明文 HTTP**，没有 TLS。口令与 token 在链路上是明文 ——
      `16/` 已经做出了 TLS 客户端（Windows SChannel，`16/src/tls.h`），
      但**这与"部署时真的开启 TLS"是两件事**，开启步骤在 `19/docs/现场作业指导书.md`。
    - ★ **跨域（CORS）2026-10-11 起默认关闭。** 原先后端无条件回
      `Access-Control-Allow-Origin: *`，等于允许**任意第三方网页**直接调本项目的 `/api/*` ——
      只要你在同一个浏览器里登录过，任一站点都能借会话读数据，而您察觉不到。
      现在默认不回这个头（托管模式下前后端同源，本来也不需要），
      确需外部页面调测时用 `--allow-origin <具体源>` 显式开 **（不能是 `*`）**。
      三者是**相乘**的：明文 HTTP × 默认口令 × 任意源可读 —— 详见 `14/docs/README.md` §6.1。
7. **侧栏品牌行（`.brand`）是固定宽度的窄槽，改文案前必须先量，不能目测。**
   侧栏固定 218px，品牌行右侧还钉着"收起/展开"按钮（`flex: 0 0 26px`，不参与收缩）。
   当前文案 `储能EMS运行平台` 自然宽 117.5px；`.brand` 水平内边距为 `12px`（与
   `.nav` 及收起态一致），余量约 14.5px。
   `.brand span` 带 `min-width:0 + overflow:hidden + text-overflow:ellipsis` 兜底：
   极端字体回退下**宁可文字打点，也绝不允许把收起按钮挤出侧栏**
   —— `.sidebar` 是 `overflow:hidden`，挤出去按钮就永久消失（再也收不回侧栏）。
   历史证据：旧文案配旧 `18px` 内边距时，Logo 已被静默压缩到 **24.8px**（声明 26）、
   文字被裁 5px —— 这类压缩肉眼看不出来，只能量（见 `CHANGES.md` §55）。
8. **三处名字目前不完全一致**（有意保留，未擅自统一）：侧栏品牌行
   `储能EMS运行平台` / 浏览器标题 `工商业储能 EMS · 运行平台` / 登录页大标题
   `工商业储能 EMS`。若要整体统一品牌名，这三处需一起改。
9. **装配视图里 9 个部件显示「无实时源」是事实，不是待办**（详见 §4）。
   补全它们的唯一途径是 `13/` 的 Modbus 接入把那些点真正采上来 ——
   界面侧已按"有源 / 无源 / 取不到值"三态如实呈现，**不会**为了让图好看而涂成正常。
10. **报表「打印 / 存为 PDF」走浏览器的打印到 PDF，没有内嵌 PDF 库。**
    这是有意的取舍：自己画 PDF 等于另起一套排版真相（字体、分页、列宽都要重对一遍），
    报表页改一个字段就得同步两处，迟早对不上。`@media print` 是同一棵 DOM，只有一份真相。
    代价是**分页位置与页边距由浏览器决定**，不同浏览器打出来可能差一页；
    且打印样式**只在打印预览里可见**，日常点开页面看不出变化（改了要打一次预览才验得到）。
11. **一次接线图的节点坐标是页面里手排的**（`pages.js` 的 `wiring()` 用 `colX(i)` 线性排布），
    不是自动布局算法。加一台设备要手改坐标；节点多了会挤，没有自动换行。
12. **告警只有「等级 × 来源」两个维度，`status` 与 `device_id` 没开筛选。**
    这不是漏做：实测 `14/data/ems.db` 的 290 行里 `status` 恒为 `active`、
    `device_id` 恒为 `DEV-BMS-01`（见 `14/scripts/probe_alarm_dims.py`）。
    给单值维度一个下拉框就是"选了永远 0 条"的假入口 —— 比不提供这个选项更糟。
