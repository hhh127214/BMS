# 15/ 平台层前端 · 运行界面

> 一句话：把 14/ 数据库里的运行数据，变成一屏能看懂、能逐拍回看、能下钻的站级运行态势。

---

## 1. 为什么需要 15/

`14/` 把仿真产物装进了 SQLite 并开了 24 个 REST 接口 —— 但接口是给机器看的。
`15/` 补的是**最后一段**：让人能看见。

三个具体判断：

1. **平台层缺了前端就不是平台层。** 框架 §3.1 的平台层定义是「数据 + 服务 + 界面」。
   只有库和接口，运维人员要自己拼 `curl`，等于没有平台。
2. **结论必须能被"看见"才可信。** `10/` 的净收益 572.01 元、`09/` 的告警分档、
   `07/` 的本拍闭环四个布尔 —— 这些数字在报告里是一行字，在这里是能逐拍回看的一天。
3. **界面是接口契约的第一道真实验证。** 24 个接口里有 401/403/404/400 四类负路径，
   写自检能覆盖，但**"页面真的渲染出东西了"**只有点开才知道。

**七个文件、4754 行、零第三方依赖、零打包步骤。**

★ `assets/assembly.js` 是**派生产物，不要手改**：源是
`docs/规划/部件测点映射表.csv`，改了 CSV 请重跑
`python 15/scripts/gen_assembly.py`（`--check` 只比对不写盘）。
它带着 CSV 原值（`src` 字段），`selftest` 的 J 段据此**逐点**比对三列 ——
这是"界面结构没与现场点表脱钩"唯一的自动拦截点。

导出前会把 CSS 变量解析成当前色值内联，避免导出图变黑块）。

## 3. 快速开始

```bat
REM  ① 先确保数据库有数据（14/ 的活）
scripts\import_sim.bat

REM  ② 起服务 + 托管界面
15\scripts\run_ui.bat
REM  浏览器打开 http://127.0.0.1:8765/
```

> **不能双击 `index.html` 打开。**
> 界面要调 24 个 `/api/*`，`file://` 协议下浏览器按跨源直接拦掉，
> 页面会停在"加载失败"。必须由 `14/src/server.py` 托管。

默认账号：

| 账号 | 口令 | 角色 | 能看什么 |
|---|---|---|---|
| `admin` | `admin123` | 管理员 | 全部 **11** 页（含用户与审计） |
| `operator` | `operator123` | 运行员 | **10** 页（能改策略、能下发指令） |
| `viewer` | `viewer123` | 只读 | **10** 页（全部只读） |

（11 = `app.js` 的 `MENU` 项数；唯一带 `minRole: 'admin'` 的是「用户与权限」，故其余两档少 1 页。）

**现场部署前必须改默认口令**（见 `14/docs/README.md` §5）。

## 4. 界面结构（11 页）

| 页面 | 主要数据源 | 关键内容 |
|---|---|---|
| 总览 | `overview` | 4 指标卡 / 640×344 能量流图（等轴测 3D 场景：**实心粗箭头**表达潮流、方向字（停机/用电/充电/购电…）写在箭头杆里，中线是 **3D 汇流柱**且「交流母线」四字竖排；名称挂图案外侧、数值在图案下方） / 本拍闭环 / 安全红线 / 告警分档 / 经济性 |
| 实时监控 | `realtime` + `overview` + `series` | **时刻查询**：滑块值域是**采样点下标**（不是秒）—— 数据有断档时按秒铺格会让绝大多数位置取不到数，见 §4.3 ＋「跳到最新」；**切页再回来停在上次那一拍**；设备实时量 / 储能与闭环 / 全天 SOC 走势（游标指当前拍） |
| 历史曲线 | `series` | 7 条曲线多选对照（关口/负荷/光伏/储能实际/指令/权限上下界）+ SOC 专图，采样 48~960 点 |
| 告警中心 | `alarms` + `alarms/summary` | **等级 × 来源 双维筛选**（可任意组合、再点一次取消）/ 两张分类统计表**可点即筛** / 24 h 小时柱状分布（已应用当前筛选） |
| 策略配置 | `strategies` | 9 个策略的开关与参数 + 仲裁优先级 + 下发指令演示 |
| 收益分析 | `economics` + `energy` | 净收益构成 / 节省率 / 日周月对比 |
| 报表系统 | `report` | 日 / 周 / 月三档 + 导出时序与告警 CSV + **打印 / 存为 PDF**（`@media print`） |
| **装配视图** | `realtime` + `assembly.js` | 柜 → 舱 → 部件的**等轴测爆炸图**：4 部位 / 14 部件 / 78 测点；点部件看它的全部测点定义 |
| **一次接线图** | `overview` + `realtime` | 12 节点 / 12 条连接，实线=主电流路径、虚线=辅助挂载（不导电）+ 当前功率 + 9 条连接清单 |
| 设备管理 | `devices` + `realtime` + `access` + `upstreamPointMap` | **两端接入**（上端链路 / 下端逐台形态，见 §4.2）+ **每端两份输入**（接入参数 + 点表 / 转发表）+ ②点表 **并入设备清册八列**（型号 / 额定值 / 状态 / 当前功率 / 接入形态）+ 逐台编辑做成**全页弹层** |
| 用户与权限 | `users` + `audit` | 用户列表 / 新建用户 / 最近 100 条操作审计（**仅 admin 可见**） |

**★ 装配视图上"多数部件是灰的"是事实，不是没做完。**
14 个部件里**只有 5 个**能取到实时值 —— `/api/realtime` 只返回
`DEV-METER-01 / DEV-PV-01 / DEV-LOAD-01 / DEV-PCS-01 / DEV-BMS-01` 五台设备。
其余 9 个部件的点要走 `13/` 的 Modbus 接入才有数，所以画成**灰的并写「无实时源」**。
把它们涂成"正常"等于谎报现场这个部件在传数据 —— 不报错、界面上什么都看不出来，
正是本项目最忌讳的失效方式。

**★ 一次接线图 ≠ 总览的能量流图。** 能量流是**能流示意**（四节点定死，
回答"电往哪走、走多少"）；接线图是**拓扑事实**（节点来自
`docs/规划/柜体装配视图.md` §2 的 9 条连接，回答"柜里有什么、怎么接的"）。
辅助舱三个部件（消防 / 空调 / 门禁）挂在柜**外**、用虚线 —— 它们不走主电流，
画进主链等于说"电流流过烟感"。

**时间轴有两个口径，由后端 `scenario.time_base` 决定。**
`sim` 口径的 `t_s` 是"一天内秒"（0~86400），`wall` 口径是 Unix 墙钟秒 ——
所以页面**不能写死轴长**：写死 86400 时，wall 数据整条轴都落在数据开始之前，
滑块能拖、每一格取到的却是同一拍。现在范围取自 `/api/series` 返回的 `t_s` 端点。

### 4.1 数据源只有一个（v1.5 的取舍，写在这里免得后人再加回去）

界面**没有**"运行模式 / 仿真模式"切换器，也**没有**数据集切换器（`normal / fault / stress`
那排按钮），菜单里**没有**「仿真」页。这不是漏做，是三条判断的结果：

| 判断 | 理由 |
|---|---|
| "数字是怎么算出来的"该由后端决定，不该让用户选 | `/api/engine` 的 `scenario` 是唯一来源；界面把它选成开关，就必然出现"界面一切正常、其实看的是三天前的仿真"，而且**没有任何东西会报错** |
| 离线批量仿真是研发侧的验证手段 | 现场用户没有"按一下跑一遍日仿真"这个动作。它留在 `10/` 的脚本里，不进产品界面 |
| 采集状态只在设备管理页说 | **v1.9 起顶部状态条已整条删除**：它挂在每页的最上方，正常时不存在、异常时把整页往下压，而真正要处理它的人只会去设备管理页。采集状态（采集中/异常 + 已入库行数）与**采集告警**现在都在设备管理页「二 · 站内设备接入」的同一行里。数据源性质（模型源 / 现场设备源 / 历史库）仍常驻**页脚** |

★ 反向断言在 `selftest` 的 [I] 段：`#engine-seg` / `#scenario-seg` 不存在、`API.setEngine` 零调用、
`buildScenarioSeg / scenarioEntry / scenarioList` 三个函数不存在 —— 入口长回来时构建会红。

### 4.2 设备管理页：两大部分 × 两种输入源（v1.7）

「设备管理」页顶上分成**两大部分**。名字按「跟谁对接」起，不用内部方位词（上端/下端）：

| 部分 | 名字 | EMS 身份 | 对端（真实 / 模拟） |
| :--- | :--- | :--- | :--- |
| 一 | **调度主站接入** | IEC 104 **从站**（被连的一方） | 上级调度主站 / 模拟调度主站 |
| 二 | **站内设备接入** | Modbus TCP **主站**（主动轮询） | 现场装置 / 设备替身 |

★ **v1.7.x 撤掉了每一部分里的「真实输入源 / 模拟输入源」并列卡片。**
那两块与 ① 接入参数 是同一份内容（对端是谁、监听在哪、CA 多少，全部就在输入框里），
画两遍只会多出一处「当前生效」标记要人自己对齐 —— 而那个标记本身还是第二个真相源
（由 `end.kind` 算），与 ① 表的形态列（由 `device_conn.source_kind` 算）迟早对不上。

现在形态与参数的归属是**一处一个**：

| 要知道什么 | 去哪儿看 |
| :--- | :--- |
| **这一端现在是真还是模拟** | 页尾「模拟输入源」面板的徽章（一个面板管两端） |
| **每一台现在是真还是模拟** | ②点表 的「接入形态」列 / ① 的「形态」列 |
| **要填什么** | 上端：点「接入调度主站」走向导（第 6 步里 ① 接入参数 真 / 模各占一栏，两列并存，互不覆盖）；下端：② 点表的 ① 接入参数，逐台一份 |
| **读得对不对** | ② 点表 / 转发表 |

留下的只有「按台整片切」两个按钮（`全部切到真实/模拟输入源`）：它改的是**每台设备**
自己的形态，与"整端切"不是一回事 —— 调试期「PCS 接真机、电表先接模拟器」是常态，
页尾那个总开关表达不了这种混接，也不该表达。

#### 页尾「模拟输入源」面板（v1.7.x → v1.11）

页面最末一张卡。**一个面板管两端**：

| 动作 | 做什么 |
| :--- | :--- |
| **启用模拟源** | 两端一起切到模拟源，按当前这一套把 ① 的模拟栏**自动填好**（每台一个端口），并**把整条链路拉起来**（替身 ×N / 采集器 / 上端网关 / 模拟主站） |
| **换一套**（循环箭头图标） | 下端端口段整体换一档：1502 → 1602 → 1702 → 1802 → 循环。**只换表，不动形态、不动进程** |
| **换一个进程**（双向箭头图标） | 停掉现有进程，按**当前这一套**把整条链重新拉起。这是 v1.10 新增的那一个按钮 |
| **关闭模拟源** | 两端一起切回真实源、收掉链路，上面的表回到真实值。**真实栏一直在，不会被清零** |

★ **为什么「换一套」和「换一个进程」要分成两个按钮**：它们改的不是同一样东西 ——
前者改**表**（表上写的端口段），后者让**真的在跑的那些进程**搬过去。合并成一个按钮
就会出现两种静默错：要么"表变了、进程没变，两套并行"，要么"为了换套把一个正在看的
采集打断"。分开之后，若进程还在旧套上，面板会明说「进程还在套 3」，并告诉你点哪个。

★ **为什么面板上有两张表**：上面那张是**计划**（表上给每台排的端口），下面那张
「链路进程」是**现实**（谁真的在听）。只有计划表时，人会以为端口真的有人应答；
而 `netstat` 一查全是空的 —— 这正是"看起来在工作"。

★ **采集器一次只连一台**（`active.conn` 是单台文件、`07/ --device modbus` 也是单目标）：
其余替身是「已监听 · 未被采集」。面板把这句话写出来，不假装 6 台都在跑。

★ **徽章写 `9/10` 还是 `9/9`**：分母是 `expected`（已扣掉 `skip`），不是 `total`。
停用的那台本来就不该起，算进分母就变成"掉了一个"，处置完全不同（一个要去查日志，
一个什么都不用做）。所以进程表里它显示「不适用」而不是「掉了」。

★ **后端重启不等于进程退出**：平台启动时会按 `meta['sim_chain_procs']` 里的 pid
把链路认领回来（`attached`），所以刚重启那几秒徽章不会短暂地撒谎说「未启动」。

★ **为什么必须是一个面板**：两块分开时"只切一端"是可能的，而
「下端模拟 + 上端真实」正是这一页唯一会骗人的组合 —— 上送调度的是替身算的数，
屏幕上却一切正常。收成一个开关是让这件事**没有办法发生**，而不是发生后弹个警告。

★ **v1.11：模拟源的表达全部收在这一张卡里**。上面那两张表（上端 ①② / 下端 ①②）
不再换配色，正文也不再铺大段说明 —— 状态只看徽章（真实源 / 模拟中）、套名、计划表与
进程表；解释挂在三个按钮的 `title` 上。撤掉配色的理由见 `app.css` 里那段注释：
那两张表回答的是"打给谁、问什么"，不是"数从哪来"；把页尾开关的状态画上去之后，
人分不清「这一列是模拟值」和「整张表都在模拟」。常驻解释同理 —— 天天看四遍的说明
活不过两天就只剩一片灰，真出事时反而找不到那句红字告警。

★ **链路没在跑就不列进程表**：关闭模拟源之后每个角色都会显示「掉了」，一屏红字看着
像坏了，其实只是没开。这个事实由徽章「链路未启动」说，不需要九行红字再说一遍。

**为什么拆成两个开关。** 两条通道本来独立：调度链路开通与设备到货是两件不同的事，
「设备已到货接真机、调度链路还没开通」是现场最常见的状态。v1.5 / v1.6 用一个整站开关
写两端，等于逼着人把两件不相干的事一起改 —— 改完屏幕上只多出几个小标签。

**不对称之处是真实的，不是没做完：**

| | 调度主站接入 | 站内设备接入 |
| :--- | :--- | :--- |
| 几套参数 | **一套**（一个监听口 = 一条链路） | **每台设备一套**（形态也按台记） |
| 怎么切 | `POST /api/data-source {end:"upstream"}` | 逐台改，或「全部切到…」整片切 |
| 采集器 | **跟它无关**（网关自己起停） | 采集器就是它：启停 / 清空都在这一部分 |
| 保存后生效 | 网关**自己启动时**读 `active.upstream` | 采集器启动时读 `active.conn` |

**每一部分内部再分 ①② 两段 —— 因为每端要的是「两份」输入，不是一份：**

| | ① 接入参数（连得上吗） | ② 点表 / 转发表（读得对吗） |
| :--- | :--- | :--- |
| **调度主站接入** | **全站唯一一份**：监听网卡 / 监听端口 / 公共地址 CA / 启用；模拟源那侧另记「模拟主站跑在哪台机器」 | **IOA 转发表**（可编辑、可保存）：IOA / 类型 / 方向 / 分组 / 名称 / EMS 点名 / 系数 / 偏置 / 单位 / 说明。随包默认表 **24 上送 + 6 下行** |
| **站内设备接入** | **每台一份**：IP / 端口 / 从站号 / 轮询周期 | **每台一份**：寄存器表 / 地址 / 编码 / **字序** / 缩放 / 可写 |

这两件事的失败方式完全不同：**地址填错是连不上**（有连接超时、有明确报错）；
**转发表 / 点表填错是连上了但数是错的**（没有任何报错，界面上数据照常在动）。
所以它们在页面上必须是两段、各有各的标题与口径说明，而不是一段里的两行输入 ——
混在一起时，人会以为"地址对上了就通了"。

> **v1.14 起这两段的位置变了，口径没变**：调度主站接入的 ①② 不再铺在设备管理页上，
> 而是搬进「接入调度主站」九步向导的**第 6 步**（九步里唯一会改软件配置的一步）。
> 上表这一行仍然成立 —— 变的是入口，不是"两份输入"这件事本身。
> 详见 `CHANGES.md` §96。

**上端的 IOA 转发表在页面上可编辑、可保存**（v1.6 起）。上方的「编辑转发表」打开一个
跟页面一样大的弹层，12 列逐行改，工具栏给「新增一行 / 导入 CSV / 下载模板 /
导出当前表 / 恢复默认 / 保存转发表」。

★ **「导入 CSV」只进编辑区，不落盘**（v1.16 起）。它是编辑动作不是提交 —— 落盘仍然只走
「保存转发表」。这样导错了能在表格里接着改，不必从文件重来。覆盖编辑区前先比一次
`dirtyPM()`（按内容签名、**排序后**比，因为行序无意义），只有真有未保存改动才确认一次。

★ **导入与下端点表有三处刻意的不同**，照抄下端会做错：
① **不校验行数** —— 上端按 IOA 定位，多一行少一行都合法（下端「行序即索引」那条约束在这里是错的）；
② 只进编辑区（见上）；
③ 导进来立刻跑一遍行内预检并把结果说出来（几行没过、第一处是哪一行、补了几处默认值），
不让用户以为"导完就好了"、等点保存才被后端拒一次。

★ **解析口径必须与 `14/src/upmapconf.parse` 同**：剥 BOM、跳 `#` 注释、首列 `ioa` 当表头跳过、
前 8 个逗号切字段剩下整体当 `note`。前端比后端宽容会出现「导进来 30 行、点保存被拒在第 7 行」，
比后端严格就把后端认得的表挡在门外。
★ **空列补默认值**（分组 1/0、系数 1、偏置 0）：服务端 `_as_int` / `_as_float` 对**空字符串是
直接报错**、不走默认值，而调度下发的那张《远动信息表》通常没有「总召分组」这一列 ——
不补，用户第一次导入真实表就会在"保存"这一步全红。

★ **`src` 仍然是必须人工过一遍的**：调度只知道「4004 是关口有功」，不知道我们内部叫
`MEAS.P_GRID`。导入只能把 IOA / 类型 / 名称 / 系数搬过来，`src` 为空的行会在表格里标红，
必须逐行绑到点表里的点名 —— 这是语义映射，不是格式转换。

★ **为什么不是只读**（这一条推翻了早先的决定）：怕「界面一套 IOA、网关另一套」是对的，
但答案不是拒绝写入，而是**把两个真相源收敛成一个文件** —— 界面写的
`config/point-map/active.pointmap.csv`，**就是**网关启动时读的那一份。只给看不给改，
等于把"改一个 IOA"变成"去 `P3/data` 改 CSV 再敲 `--point-map`"，而那人通常不是
最熟悉这个系统的人。

保存走 `PUT /api/upstream/point-map`：过校验 → 原子落盘 → 整表重写库存档，
任一步失败**文件与库一起退回**。「恢复默认」是 `DELETE`（删文件 + 清库存档），
**不是存一个空表** —— 空表会被 400 拒（「文件不存在 ≠ 没配置」）。

★ **不会热更新**：网关只在**启动时**读转发表，页面上写死了这一句 ——
改完要**重启网关**才生效。不写这句，人会以为"保存了怎么没生效"。

② 段本身仍保留**当场对账**的价值：来源徽章（`平台已保存` / `随包默认`）、行数、
上送 / 下行点数、保存时间与操作人，以及加载顺序说明
（`--point-map` → 约定路径 `active.pointmap.csv` → 内置默认表）。

**采集中不许切下端**（后端 409、按钮置灰）：那等于把采集器脚下的对端换掉，而它还在按
旧参数读写。切上端是允许的 —— 网关不热更新，改它不会半途换对端。

**两端组合的提示由后端算（`ds.mix`），界面不自己推。** 三种语气对应三种事实：

| 组合 | 等级 | 说的是什么 |
| :--- | :--- | :--- |
| 下端模拟 → 上端真实 | **红** | 上送调度的是替身算出来的数，不是现场值 |
| 下端真实 → 上端模拟 | 灰 | 现场数据只送本机模拟调度，不外发（调度开通前的常规调试态） |
| 上端还没登记链路 | 橙 | 网关会用内置默认（真实源 · 2404 · CA 1），建议联调期显式设成模拟 |

都画成红就等于都不红 —— 所以只有第一种是红的。

**上端不画连接状态灯。** 平台**不回采**上端链路的连接数（网关不往上汇报），
所以只有一行如实说明：*平台不回采上端连接状态，请在网关侧看网关的 `[CONN]` 行*
—— 点一个查不到来源的绿灯，比不点更坏。

**「全部切到…」必须报 k/N**（`已改为真实输入源 4/6 台`，并把失败台数与第一台的原因写进
文案）。批量操作最危险的不是失败，是**部分失败而界面显示全成功** —— 现场留下的半真半模拟
状态，事后没人能复现。**切到模拟方向还要二次确认**：那是"看起来最正常"的一种错。

**②点表 的前八列是「清册」**（设备号 / 类型 / 接入形态 / 额定功率 / 额定容量 / 状态 /
当前功率 / 说明），排在「点数 / 点表状态 / 编辑」之前。接入形态
（`真实源` / `模拟源` / `未配置`，三态徽章）数据来自 `/api/access` 的逐台明细 ——
**不是前端自己按 `host` 是否为空推的**。推出来的"形态"会和端侧实际行为分叉。
逐台形态与两大部分的当前形态**可以不一致**（就是"按台记"的意义），不一致时以每台为准。

**为什么把清册并进点表，而不是各占一张卡**：判断"这台的点表该不该改"要同时看
"这台是什么型号、有没有在采、现在多少功率"和"它读哪些寄存器"。分在两处，人只能靠
设备号在脑子里对 —— 而设备号是六台里唯一没有语义的那一列。合在一行之后，
一行就能回答"这台要不要动"；分成两张卡时，中间还隔着两屏。

**逐台编辑里的「① 接入参数」卡也跟着改了**：多了「对端形态」下拉与两个模拟源字段，
保存后 toast 会说出**实际对端**（模拟源时写 `127.0.0.1:1502（★ 不是真机）`，
真实源时写真实地址）—— 保存成功与"连到哪儿"是两件事，都要说。

> 界面上"形态"这个词之所以必须常驻显示：调试期用模拟源、投运切真源是标准流程，
> 危险的是**忘了切回来**。那时数据在动、告警正常、没人会怀疑 —— 因为模拟器在替真设备说话。

**页面上只剩两张卡**：`一 · 调度主站接入`（**v1.14 起收成一个入口卡**：
`接入调度主站` + `重置` + 九步进度徽章 + 当前生效值；九步填报在全页弹层里走完，
原来的 ① 接入参数 / ② IOA 转发表 都在向导第 6 步内，见 `CHANGES.md` §96）/
`二 · 站内设备接入`（① 接入参数 + ② 点表）；「点表口径」（点名与索引**不另抄一份**，
取自 `07/src/rtdb/ems_point_table.h`）仍在下端那一段里。

**逐台编辑是一层弹层，不是页面末尾的一块。** 它里面是 9 列 × 32 行的点表，
铺在页面上会把整页撑到三千像素，而且滚动位置一乱就分不清"滚到哪了"。
所以点任一行的「编辑」打开一层**跟页面一样大**的弹层
（`.mdl { position: fixed; inset: 0 }`，内部自己滚），Esc 或「关闭」返回。

| 层 | 回答什么 | 数据来源 |
| :--- | :--- | :--- |
| **②点表 · 清册八列** | **这台是什么、现在什么样**（型号 / 额定功率 / 额定容量 / 状态 / 当前功率 / 接入形态）—— 只读 | `GET /api/devices` + `/api/realtime` + `/api/access` |
| **逐台编辑（弹层）· `<设备号>`** | 改**这一台**的两份输入：① 通信参数（对端形态 / 地址 / 端口 / 从站号 / 周期 / 超时 / 备注）+ ② 点表（表 / 地址 / 编码 / 字序 / 缩放 / 可写，逐行预检） | `GET/PUT /api/devices/{id}/conn`、`GET/PUT /api/devices/{id}/point-map` |

**弹层页头必须带设备号**（`逐台编辑 · DEV-BMS-01`）。它里面那两张卡
（① 接入参数 / ② 点表）都是**逐台**的，页头不写这一句，人会把它们当成
「又一次全站的两份输入」，而实际上只作用于下拉里那一台。设备号只写**一处**
（弹层页头），卡片自己不挂标题 —— 两处都写反而不知道该看哪个、改的是不是同一台。
弹层按 `key` 复用：页面来回切不会每切一次就往 `body` 上多挂一层。

**弹层的 `z-index` 必须低于 toast**（90 vs 999）：点完「保存点表」的反馈要浮在弹层之上，
否则保存成功看不见，人会以为没存上、再点一次。

**分界为什么在这里**：上半的 ①② 决定「数据从哪来、长得对不对」（整站 / 每台一份配置）；
②点表 上的清册列只是**读**（不配置任何东西），弹层里的逐台编辑才是改单台配置的入口。
改错地址是连不上（有报错），改错点表是连上了但数错（不报错），
所以只有点表逐行带「预检」列。

### 4.3 实时监控页的时间轴：值域是采样点下标，不是秒

滑块 `min=0 / max=N-1 / step=1`，每个位置对应 `/api/series` 返回的第 i 个采样点。

**为什么不能按秒铺。** 早期实现把 `[首拍, 末拍]` 铺成 864 格，拖动时把秒值发给后端，
后端取「≤ t 的最后一拍」。`sim` 口径下（8640 拍均匀的 24 h）两者等价；
但 `live` 是**跨会话累积**的 —— 库里实测横着 9-30 的 12 h 与 10-18 的 12 min，
中间空 18 天。轴按整段算 ⇒ 步长 ≈1812 s，**约 97% 的位置落在空档里**，
后端一律回落到同一个旧拍：拖动有反应、画面纹丝不动，看着像卡死。
改成下标后，断档只表现为"某一格跳得远"，不存在取不到数的位置。

两条配套约定：

- **取不到采样点就发 `-1`**（后端语义 = 最新一拍），**不发 0** ——
  `wall` 口径下 `t_s=0` 是 1970 年，后端必然 404，页面直接进错误态。
- **「跳到最新」现取末点的值**，不用闭包里缓存的 `t`：拖过轴之后 `t` 是旧值，
  点"最新"会把人送回刚才那一拍。

## 6. 权限与可见性

- 侧栏菜单按角色过滤（`app.js` 的 `MENU[].minRole`），非 admin **看不到**「用户与权限」。

- **这只挡前面。真正的门在后端**：`14/src/api.py` 的 `ROUTES` 每条都带最低角色，
  越权请求返回 403、未登录返回 401。前端的过滤是体验，不是安全边界。

  `{"accepted": false, "executor": "none", ...}`，界面显示"本次只记录意图并审计"。

9. **装配视图里 9 个部件显示「无实时源」是事实，不是待办**（详见 §4）。
   补全它们的唯一途径是 `13/` 的 Modbus 接入把那些点真正采上来 ——
   界面侧已按"有源 / 无源 / 取不到值"三态如实呈现，**不会**为了让图好看而涂成正常。
10. **报表「打印 / 存为 PDF」走浏览器的打印到 PDF，没有内嵌 PDF 库。**
    这是有意的取舍：自己画 PDF 等于另起一套排版真相（字体、分页、列宽都要重对一遍），
    报表页改一个字段就得同步两处，迟早对不上。`@media print` 是同一棵 DOM，只有一份真相。
    代价是**分页位置与页边距由浏览器决定**，不同浏览器打出来可能差一页；
    且打印样式**只在打印预览里可见**，日常点开页面看不出变化（改了要打一次预览才验得到）。
11. **一次接线图的节点坐标是页面里手排的**（`pages.js` 的 `wiring()` 用 `colX(i)` 线性排布），
    不是自动布局算法。加一台设备要手改坐标；节点多了会挤，没有自动换行。
12. **告警只有「等级 × 来源」两个维度，`status` 与 `device_id` 没开筛选。**
    这不是漏做：实测 `14/data/ems.db` 的 290 行里 `status` 恒为 `active`、
    `device_id` 恒为 `DEV-BMS-01`（见 `14/scripts/probe_alarm_dims.py`）。
    给单值维度一个下拉框就是"选了永远 0 条"的假入口 —— 比不提供这个选项更糟。

## 附：跨模块口径

- **字段名不另抄一份。** 前端的量测键名（`p_grid_kw` 等）与 `07/src/rtdb/ems_point_table.h`
  、`14/schema.sql` 的 `realtime_data` 列名同源。本项目曾因手抄品质常量出过事故
  （`P3/docs/README.md` §7.1：值全对、测试全绿，只是调度画面上 24 个点全灰）。
- **数据集名由后端给，前端不再维护第二份名字表**（v1.5 删掉了 `scenarioEntry()` 的短名映射）。
  页脚显示的名字直接取 `health.scenarios[].name` 的 ` · ` 之前那段。
- **时标**：`sim` 口径 `t_s` 是仿真秒（0~86400，采样 8640 拍）；`wall` 口径是 Unix 墙钟秒。
  判据在后端 `scenario.time_base`，前端按 `/api/series` 返回的 `t_s` 端点定轴。
