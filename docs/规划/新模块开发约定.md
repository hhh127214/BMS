# 新模块开发约定（16/ 17/ 18/ 19/ 及后续）

> 本文件是**新增模块时的施工规范**。它不是新规则 —— 是把仓库里既有的、
> 散落在 `docs/交接/下一步工作交接说明.md` §0 与各模块源码注释里的做法**收拢成一份**。
>
> 为什么要有这份：新增模块最容易犯的错不是"写不出代码"，而是**写出来了但没接进
> 构建树** —— 上游 `储能协调控制器实时数据库与缓存模块详细设计/src/lvrt_agent/`
> 就是先例：源码写完、`build/` 下没有对应 exe、从未被编译过，实测跑起来功能是死的。
> 本项目的对策写在 §10.4 D2：**每个新文件都必须挂进 `scripts/build_all.bat` 的分步号**。

## 1. 工具链与编译

| 项 | 值 |
| --- | --- |
| 编译器 | MinGW-w64 **g++ 8.1.0**（`/c/Program Files/X64/mingw64/bin/`） |
| C++ 标准 | **C++17**（`-std=c++17 -Wall -O2`） |
| C 标准 | **C11**（`-std=c11`，仅 RT_DB 相关 `.c` 用） |
| 套接字 | Windows 需链 `-lws2_32` |
| 第三方依赖 | **零**（唯一例外是 `P3/` 的 `vendor/lib60870`） |
| 代码形态 | 以 **header-only** 为主（`src/*.h` 全部 inline）；只有需要跨 C/C++ 共享的符号才落 `.c` |

> ⚠️ **g++ 8.1 的坑**：`<filesystem>` 需额外链 `-lstdc++fs`，`<charconv>` 整型转换
> 在该版本上不完整。**新模块避开这两个头**，用 `<string>` + 手写转换。

跨模块 `#include` 是**扁平**的（`#include "xxx.h"` 不带路径），靠 `-I` 解析 ——
所以搬头文件到别的模块**不用改任何 include**，只要给该模块配好 `-I`。

## 3. 测试框架：项目自带的 `EXPECT_*`（**不用 gtest**）

照 `13/tests/test_modbus_tcp.cpp` 抄。最小骨架：

```cpp
static int g_pass = 0;
static int g_fail = 0;

#define EXPECT(cond)                                                      \
    do {                                                                  \
        if (cond) { ++g_pass; }                                           \
        else { ++g_fail;                                                  \
               std::cerr << "  FAIL  " << __FILE__ << ":" << __LINE__     \
                         << " : " << #cond << std::endl; }                \
    } while (0)

#define EXPECT_EQ(a, b)   /* 同上，long long 比较 */
#define EXPECT_NEAR(a, b, eps)  /* 同上，double 比较，带 eps */

int main() {
    /* ... 逐条用例 ... */
    std::printf("\n");
    if (g_fail == 0) std::printf("ALL TESTS PASSED\n");
    std::printf("PASS=%d FAIL=%d\n", g_pass, g_fail);
    return g_fail == 0 ? 0 : 1;
}
```

**结尾必须印 `PASS=%d FAIL=%d`** —— 全量基线就是靠这一行的数字加总的。

### 3.1 判据要"有区分度"

本项目的核心教训（`docs/规划/模拟器与设备接入梳理.md` §10.1 A2）：

> **先造出能区分对错的可观测差异，再谈修好。**

反例：A2 把"读电表"改成正确实现后，在**所有既有夹具下逐位恒等** ——
编译、单测、验收全绿，但把代码退回去**一条断言也不会红**。
后来给设备侧加了可注入的系统偏差，判据才第一次有区分度。

所以每条**关键**断言都要问：**"把实现故意改错，这条断言会红吗？"**
不会红的话，它测的是别的东西。

### 3.2 反向守卫

硬判据（`== 0` 这类）前面常配一条**反向守卫**，证明"测试确实测到了东西"：

```cpp
EXPECT(collisions() > 0);          // ① 真的撞上了，才说明测到了
EXPECT(stale_reads() < collisions()); // ② 碰撞被重试吸收
```

没有①的硬判据可能只是"条件没被触发"，而不是"实现正确"。

## 4. `.bat` 脚本：三条硬规矩（都是静默失败）

### 4.1 不能从 Git Bash 直接跑

仓库路径可能含括号（本机 `D:\wb(cn)\BMS`）。MSYS 把命令交给 cmd 时不给路径加引号 →
`(cn)` 被当成命令分组。**用 Python 起子进程**，命令行里只出现裸文件名：

```python
subprocess.run(['cmd', '/c', 'build_test.bat'], cwd=r'D:\wb(cn)\BMS\NN\scripts')
```

### 4.2 块内禁用 `%VAR%`，改用 `!VAR!`

cmd 解析 `if (...)` / `for (...)` 块时，会把 `%CD%` 的**展开结果**再当语法扫一遍。
路径里的 `(cn)` 会被认成子表达式括号，块结构当场错乱 ——
整个 `.bat` 在**执行任何一行之前**就报「此时不应有 ...」并以 255 退出。
延迟展开发生在解析之后，展开结果不参与语法分析，故安全：

```bat
setlocal enabledelayedexpansion
if "!EMS_PYTHON!"=="" (
    set "EMS_PYTHON=!CD!\.venv\Scripts\python.exe"
)
```

> 注：**只对路径类变量**（名字含 `CD` / `PATH` / `DIR` 等）强制要求 ——
> 非路径变量的展开结果里不会有括号。这条检查已做成工具，见 §4.4。

### 4.3 必须 CRLF，且防「吞 CR」

UTF-8 的 `.bat` 被 CP936 读取时，若某行末尾落在双字节字符的前导字节（0x81–0xFE）上，
该字节会与行尾 `\r` 配成一对被吃掉 → 下一行的 `REM`/`echo` 前缀被吞，整行中文被当命令执行。
**退出码仍是 0**。

### 4.4 写完必须过一遍修复器

```bash
python scripts/fix_bat_encoding.py --check    # 只报不改，非 0 表示有隐患
python scripts/fix_bat_encoding.py            # 就地修复（CRLF + 行尾补空格 + 转 UTF-8）
```

它管三类：① LF 行尾 ② CP936 吞 CR ③ 块内路径变量展开。
**新写的 `.bat` 必须先过 `--check` 再提交。**

### 4.5 环境缺失要"显式 SKIP"，且**打印状态行**

需要外部运行时（Python / pymodbus / Node）的层，缺失时打印 `SKIPPED=N` 并以 **0** 退出
—— 环境问题不是代码缺陷。但**必须显式喊出来**，且**每次都打印**（哪怕是 0 条跳过）：
只在缺失时才打印的话，"确实跑了"在日志里就**没有正面证据**，只能靠"没有那一行"推断，
而"缺行"与"grep 写错 / 日志被截断"完全无法区分。

## 5. 模块文档 `docs/README.md` 的写法

照 `13/docs/README.md` 与 `11/docs/README.md` 的结构。必有的几节：

1. **它在整个工程里的位置**（一张依赖方向图 + 与相邻模块的边界）
2. **设计决策与"为什么"**（不是罗列功能，而是"为什么这样选、不这样选会怎样"）
3. **踩坑记录**（本项目最看重的一节 —— 每个坑写清：现象 / 根因 / 修法 / 判据有效性）
4. **测试清单**（用例 → 覆盖 → 关键断言）
5. **已知边界**（**必须诚实**，不做的不写"已完成"）
6. **目录结构 + 依赖方向 + 编译参数**

### 5.1 措辞约定（硬要求）

> 本项目**尚未全部完成，只是阶段性结果**。所有表述一律写
> **「已完成 / 阶段成果」**，**不要写「交付 / 交付物」**（工程文档内部术语除外）。

### 5.2 基线数字的口径

全量基线有**四个合法值**（取决于环境），写文档时必须说明用的哪个口径。
本文件写就时的口径见根 `README.md` 的「四口径表」—— **以那一张表为准**，
不要在本文件里复制数字（会过期）。

## 6. 构建树接入（**新增模块的最后一步，不能忘**）

新模块必须挂进 `scripts/build_all.bat`：

```bat
echo NN/MM NN\ 模块名（一句话）
call NN\scripts\build_test.bat || set FAIL=1
```

- **步号必须连续**（1..N 无缺号）—— `12/` 的验收器 A7-04 会校验，缺号或分母混用会**验收红**。
- 横幅分母与总步数必须一致（历史事故：扩步数时只改了最后一行，前 31 行仍是旧分母）。
- 改完跑一遍全量，确认末行是 `[BUILD ALL OK] All N components built.` 且 `FAIL=0`。

> **这一条由集成方统一执行**（避免多个工作流并发改同一个文件互相覆盖）。

## 7. 纪律速查（踩过的，别再踩）

1. **同一文件的多次编辑必须串行** —— 同一批里对同一文件发多个编辑会相互覆盖
   （实测 9 个编辑只生效 2 处）。批量替换用**单进程脚本**，末尾断言目标串剩余数为 0。
2. **批量改数字必须带边界** —— 把 `"20 / 22"` 换成 `"20 / 29"` 时，
   正文里的 `"220 / 220 拍"` 会被误伤（前者是后者的子串）。用
   `(?<!\d)20 / 22(?!\d)`，改完回头断言原始口径串还在。
3. **改公共契约用「只读视图」，不要改公共结构体** ——
   `RealtimeSnapshot` / `DeviceLimits` / `PowerCommand` 波及 `05`~`10` 与 `P1/P2/P3`。
   需要扩展时加单向映射的视图（见 `04/src/data_models.h` §2.5）。
4. **`execute()` 的返回值不可信** —— 真机里它只是"把指令发出去"，实际值要等下一拍
   `read_snapshot()`。闭环一律以量测为准。
5. **区间矛盾 ≠ 紧急** —— 满充 + 光伏大发 + 不许倒送 → 本拍无可行非零功率 →
   映射 **DERATED（可自恢复）**，绝不能锁存 EMERGENCY。
6. **故障后不自动带载是安全规程，不是缺陷。**
7. **不要碰 `code/`** —— 那是另一个项目的只读平铺副本，`.gitignore` 排除的。
8. **不要打破模块编号** —— `01`–`10` 与周期一一对应，`11`/`12` 是周期 11/12，
   `13`~`19` 是产品化与工程加固模块。
