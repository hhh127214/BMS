# 柜体装配视图 —— 爆炸图与一次接线图的共用地基

> **为什么需要这份文档**
>
> 之前有两份清单各覆盖一半，缺的正是「柜里有什么」这件事：
>
> | 已有 | 覆盖的维度 | 缺什么 |
> | --- | --- | --- |
> | `部件测点映射表.csv`（78 行 × 9 列） | 部件 ↔ 测点（**点位维度**） | 部件装在哪、彼此什么关系 |
> | `链路协议清单.csv`（3 列 × 27 条） | 部位 ↔ 链路 ↔ 协议（**通信维度**） | 柜内物理结构与电气连接 |
>
> 两份都没有把部件组织成**一棵装配树**，于是「爆炸图」与「一次接线图」无从下手 ——
> 画图的几何可以现做，但"柜里有几个舱、哪个部件归哪个舱、电流从哪走到哪"
> 属于**业务口径**，必须先定，否则图就是画师自己编的，与现场对不上。
>
> ★ **本文档是派生产物，不是原始材料。** 所有部件、点数、部位都从上面两份 CSV 取，
>   不手抄一份 —— 校验方法见 §5。手抄的清单一定会和源头脱钩，而这类脱钩
>   **不会让任何断言变红**（`CHANGES.md` §31 记过同一类教训）。

## 1. 装配树（柜 → 舱 → 部件）

```
工商业储能柜（1 台）
│
├─ ① 电池舱                         32 点
│   ├─ 电池簇                        8  簇电压/电流/温度、SOC、SOH、剩余可充放、循环次数
│   ├─ 电芯（模组内单体）              8  单体最高/最低电压与编号、压差、最高/最低温度与编号
│   ├─ 绝缘监测                       2  绝缘电阻、漏电流
│   ├─ 直流接触器                     4  主正、主负、预充继电器、充电状态位
│   └─ BMS 主控                      10  通信/数据有效、禁充放位与原因码、允许充放功率、告警级别与码
│
├─ ② PCS 舱                         17 点
│   ├─ PCS 变流器                    14  有功/无功、直流侧 U/I、交流三相 U/I、模式、故障、通信、限功率原因、电量、运行小时、模块温度
│   └─ PCS 指令落点                   3  有功设定、允许上/下界、启停遥控
│
├─ ③ 辅助舱                         17 点
│   ├─ 消防主机                       5  主机状态、烟感、温感、喷洒释放、灭火装置压力   ← 选配
│   ├─ 空调 / 液冷机组                7  柜内环境温度、回风温度、进出水温、流量、水泵状态、启停/目标温度（遥调） ← 选配
│   ├─ 门禁 / 安防                    2  柜门磁、水浸                              ← 选配
│   └─ 配电 / 开关                    3  交流断路器分合、脱扣原因、急停按钮             ← 选配
│
└─ ④ 站级（柜外，站内一次）             12 点
    ├─ 关口电表                       9  关口功率、三相 U/I、频率、正反向电能、需量、通信、分路功率、变压器容量、契约需量
    ├─ 变压器                         2  绕组/油温、负载率
    └─ 光伏逆变器                     1  光伏出力
```

**合计 4 部位 · 14 部件 · 78 点**（与 `部件测点映射表.csv` 逐行对齐）。

★ 为什么把「电池舱」放在最前、**「站级」放在最后**：前三个是**柜内**，第四个是**柜外**。
爆炸图按这个顺序由内向外展开；一次接线图则相反 —— 电流从电网（站级）流向电池（柜内），
所以接线图的主流向是 ④ → ③ → ② → ①。

## 2. 一次接线关系（电气链）

```
   电网 ◄────────────► 关口电表 ◄──► 变压器 ◄──► 站内母线
                                                    │
                       光伏逆变器 ◄──────────────────┤
                                                    │
                       交流侧断路器 ◄────────────────┤      （③ 辅助舱 · 配电/开关）
                                                    │
                       PCS 交流侧 ◄─────────────────┘      （② PCS 舱）
                            │  AC/DC
                       PCS 直流侧                          （② PCS 舱）
                            │
                       直流接触器 主正/主负/预充             （① 电池舱）
                            │
                       电池簇 ── 电芯                       （① 电池舱）
```

| # | 从 | 到 | 电流性质 | 依据（`链路协议清单.csv`） |
| --- | --- | --- | --- | --- |
| 1 | 电网 | 关口电表 | AC | `站内·一次` 关口电表 → EMS |
| 2 | 关口电表 | 变压器 | AC | `站内·一次` 变压器 / 负荷 |
| 3 | 变压器 | 站内母线 | AC | `站内·一次` 变压器温控器 → EMS |
| 4 | 光伏逆变器 | 站内母线 | AC | `站内·一次` 光伏逆变器 → EMS |
| 5 | 站内母线 | 交流侧断路器 | AC | `站内·一次` 交流侧断路器 / 并网开关 → EMS |
| 6 | 交流侧断路器 | PCS 交流侧 | AC | `柜内·跨舱` 储能柜内 BMS ←→ PCS ←→ 簇 |
| 7 | PCS 交流侧 → 直流侧 | — | AC→DC | 变流器内部，非独立部件 |
| 8 | PCS 直流侧 | 直流接触器 | DC | `柜内·电池舱` 直流侧主正 / 主负接触器 · 预充继电器 |
| 9 | 直流接触器 | 电池簇 | DC | `柜内·电池舱` 电池簇内部（电芯采样 · 模组 BMU） |

★ **第 7 步要单独点出**：PCS 的 AC/DC 变换在**同一个部件内部**完成，
接线图上不能画成两个节点 —— 否则会让人以为中间还有一台设备要接。

★ **辅助舱的三个部件（消防 / 空调 / 门禁）不在主电流路径上**，它们是**辅助用电与保护**，
接线图里挂在柜体轮廓上、不与主链串联。这不是偷懒，是物理事实：
把消防画进主链等于说"电流流过烟感"，现场会当场指出画错了。

## 3. 两个用途怎么用这份口径

### 3.1 爆炸图（点部件看实时数据）

- **展开方向**：等轴测视角，四个部位沿斜上方错开，柜内三个舱在前、站级在后。
- **点部件 → 显示该部件的全部测点当前值**。部件与测点的对应**直接取 CSV 的第 2、3、4 列**，
  不在前端另写一份清单。
- 部件颜色按**状态**而非按部位：有告警的部件变色，让"哪个部件出问题"一眼可见。

### 3.2 一次接线图（拓扑图）

- 节点 = §2 的 9 条连接涉及的**部件**（不是测点）。
- 连线粗细 / 箭头方向 = **当前功率大小与方向**，取 `overview.power` 的四个量：
  光伏 `pv_kw`、负荷 `load_kw`、关口 `grid_kw`、储能 `battery_kw`。
- ★ 与既有 `energyFlow` 的区别：`energyFlow` 是**四节点定死**的能流示意
  （光伏/储能/母线/负荷/电网）；一次接线图的节点**由本口径动态定义**，
  多一台设备就多一个节点，不是把四张图改个标题。

## 4. 派生纪律（改源头文件后必须重跑）

部件与点数**一律从 CSV 派生**，校验命令：

```bash
python - <<'PY'
import csv, collections
txt = open('docs/规划/部件测点映射表.csv', 'rb').read().decode('utf-8-sig')
rows = [r for r in csv.reader(txt.splitlines()) if any(c.strip() for c in r)]
hdr, body = rows[0], rows[1:]
g = collections.Counter((r[0], r[1]) for r in body)
print('部件数 %d / 总点数 %d' % (len(g), len(body)))
for k, n in sorted(g.items()): print('   %-10s %-12s %d 点' % (k[0], k[1], n))
PY
```

期望输出：`部件数 14 / 总点数 78`，且 14 行的部位与部件名与 §1 完全一致。

★ 这条校验已挂进 `15/tests/selftest.js` 的 J 段（装配视图一致性），
改了 CSV 不同步本文档与前端常量，自检会红 —— 这是本文档**不会过期**的唯一保障。

## 5. 已知边界（诚实记录）

1. **§2 的电气链是工商业储能的标准拓扑**，但具体到某个厂家会有差异
   （如是否有独立的汇流柜、PCS 是否多路）。本口径描述的是**单柜单 PCS 单簇组**这一档，
   多机并联拓扑尚未定义（`docs/交接/下一步工作交接说明.md` 把它列为真正开放的缺口之一）。
2. **辅助舱四个部件是选配**（`data/mod_*.json` 运行期加载）。没装的柜型，
   爆炸图上这些部件**必须显示为"未装配"而不是画出来** —— 画了等于谎报现场有这个部件。
3. **部件内部的几何位置（前后左右）本文档没有定义**，爆炸图用的是按部位分组的
   逻辑展开，不是厂家装配图。真要做成"装配指导"级别的爆炸图，需要厂家提供机械图纸。
