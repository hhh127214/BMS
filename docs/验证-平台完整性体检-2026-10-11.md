## 2. 设计内的"不完整"（不是缺陷，界面已如实告知）

这些**看着像"没做完"，其实是刻意的**，并且界面上有对应文案 —— 列出来是为了避免被误报为缺陷。

1. **真机数据源不开放**：`14/src/engine.py:99-126` 的 `SOURCES` 里 `device` 的
   `available=False`，`why` 字段写明"接真机会**真的向 PCS 下发功率指令**，前置条件是
   ①填接入参数 ②先用只读核对点表 ③现场确认后再加 `--control`"。
   界面据此标注「（模型源，不是真实电站）」（`engine.py` 的 `source_is_model`，不写死）。
2. **点表未配置回落基线**：`GET /api/devices/DEV-BMS-01/point-map` 实测返回
   `configured=False, source=baseline, rows=32`；页面把它显示成
   `未配置（回落内置默认表）` + `b-warn` 徽章（`15/assets/pages.js:1900`），
   并在页脚解释"标「未配置」的设备会回落内置默认表继续跑"（`:2037`）。
3. **告警不做"已恢复"筛选**：`alarm.status` 实测 **53/53 全是 `active`**
   （`importer.py` 写死），给它一个筛选下拉就是"恒 0 条"的假入口 ——
   `14/src/api.py:494-498` 有整整一段注释说明为什么不开放。
4. **业务运行模式不产生数据**：`run_mode` 是"业务口径 + 联动启停策略"，
   4 个模式实测 `active` 只有 1 个（backup）；它决定的是 KPI 口径与绑定的策略，
   不改变数据本身。这不是缺功能。
5. **live 数据集无不变量**：`/api/overview?scenario=live` 实测 `invariants[0]` ——
   实时流没有离线不变量汇总，是设计（不变量属离线仿真）。

## 3. 真缺口（该补没补）与最小补法

### 3.1 设备级数据通道：有读无写的表（#1 #2 同源）

**实测**：`realtime_data` **0 行**、`device_point_map` **0 行**、`device_conn` **0 行**；
`/api/devices/{id}` 对 6 台设备逐台探，`latest_realtime` **全是 `None`**。

**根因**：`13/` 采的数进 **RT_DB 共享内存**，与 SQLite 之间**没有桥接进程**；
`realtime_data` 全仓库只有 1 处读（`api.py:307`），**0 处写**。

**连带后果**：装配视图 14 个部件里只有 **5 个**绑定了实时设备（`/api/realtime` 实测 5 台：
METER 400 / PV 0 / LOAD 254.655 / PCS −143.345 / BMS `None`），其余 **9 个恒灰**。

**补法（三选一，推荐顺序）**：
1. 加桥接进程：读 RT_DB（复用 `P3/src/RtDbReadOnlySource` 只读模式）→ 按
   `17/src/point_mapping.h` 映射 → 落 `realtime_data`（根治，但要新模块）；
2. 给 `13/` 的 probe 加 `--dump-json`，由 `importer.py --live` 吃进去（改动面最小）；
3. 让 `/api/devices/{id}` 优先读 `realtime_data`、读不到再回落（至少让"死表"看得出来是空的）。

### 3.2 告警层只接了一半（#3 #4）

**实测**：`alarm.source` 只有 5 类（FSM 43 / COMM 6 / TEMP 2 / TRANSFORMER 1 / SOC 1），
`alarm.device_id` 4 类（BMS 48 / METER 2 / PCS 2 / TR 1）—— 都是 `importer.py:467
_source_to_device()` 从 source **派生**的，不是独立字段；`alarm_type` 更是 source 的副本。

**缺口**：`20/` 的告警模型有 **9 类 source + `source_id` + SET/CLEAR 配对**，
但 `14/` **零引用**（`grep 20/` 无命中）。因此：
- 没有"已恢复"（`status` 恒 active）；
- 没有"部位"维度（`链路协议清单.csv` 的 8 部位只在 `importer.py` 注释里提过，无列无代码）；
- "按设备"分类数据已够（4 取值）但 `/api/alarms` 没有 `device_id` 参数 —— 筛选没实现。

**补法**：接 `20/` 的装配器拿到 SET/CLEAR 与 `source_id`；"按设备筛选"照 `source` 的三行加
（**必须同时补断言** —— `importer.py:443-444` 自陈新增故障位没跟上会**静默退化**成
`DEV-BMS-01`）。

### 3.3 接线图箭头方向（#5）

`15/assets/ui.js` 的箭头按**拓扑**方向画（`to` 节点），`pages.js:1313-1331` 的
grid→meter / contactor→cluster 方向写死。**购电+充电**时恰好与真实潮流一致，
**放电或售电时箭头与实际电流相反**，只能靠 label 正负号分辨。总览的 energyFlow 有方向感知，
接线图没有 —— 同一张网两套箭头规矩。

### 3.4 登录死锁（#6，§63.7 挂账未修）

run 模式 + 数据源 live + 引擎未启动 ⇒ `/api/overview` 404 ⇒
`15/assets/app.js` 的 `renderPage()` 异常冒泡回登录流程 ⇒ **口令正确却进不去**；
且要切回 sim 模式**必须先进入界面** ⇒ 死锁。

**当前没暴露**：引擎正在跑（`live_state=running`，22:25 启动，`live_rows` 17），
live 数据集实测 `200`（`step_rows=24`）。但**场景仍存在**，现场关掉引擎再重登就会撞上。

**补法**：`renderPage()` 包 try-catch + 空状态页；运行模式无数据给占位页；登录页能切模式或至少提示。

### 3.5 前端没有端到端渲染判据（#7）

`15/tests/selftest.js` 是 Node 静态契约（现 327 条，含 [L] 语法守卫、[M]/[N] 沙箱实测），
但**不能证明"页面真的渲染出东西了"**；`15/tests/e2e_probe.html` 存在却**未自动化**。

### 3.6 部署前置（#11）

无 TLS（裸 `ThreadingHTTPServer`）+ 默认口令 `admin/admin123` 等；CORS 已于 §61 收紧并加了断言（§62）。
