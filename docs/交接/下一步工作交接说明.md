### 0.3 ⚠️ 两个必踩的坑（先看，省几小时）

**坑一：`.bat` 不能从 Git Bash 直接跑。**
项目根路径含括号 `(cn)`，MSYS 把命令交给 cmd 时不给路径加引号 → `D:\wb(cn)\BMS\...`
里的括号被当成命令分组 → 报 `'D:\wb' 不是内部或外部命令`（退出码 1）。
`cmd //c` 与 `MSYS_NO_PATHCONV=1` 都无效。**可行做法**：用 Python 起子进程 ——

```python
subprocess.run(['cmd', '/c', 'build_all.bat'], cwd=r'D:\wb(cn)\BMS\scripts')
# 命令行里只出现裸文件名（无括号），bat 内部的 %~dp0 会自行展开为绝对路径
```

**坑二：`.bat` 必须 CRLF 行尾，且中文行要防「吞 CR」。**
两个问题都**静默失败、退出码仍是 0**：
① LF 行尾 → cmd 解析出乱码命令；
② UTF-8 被 CP936 读取时，若某行末尾落在双字节字符的前导字节（0x81–0xFE）上，
该字节会与行尾 `\r` 配成一对被吃掉 → 下一行的 `REM`/`echo` 前缀被吞，整行中文被当命令执行。
**修法**：写完转 CRLF；模拟 CP936 扫描（`i += 1 if (c<0x80 or c==0x80 or c>0xFE) else 2`），
越界（`i > n`）的行末尾补一个空格。

## 2. 明确的边界：现在**还不能**做什么

这一节是交接的重点。**不要因为「测试全绿」就以为能上现场**，以下是真实缺口。

### 2.1 没有生产装配线（最关键的缺口）

- 结论：**至今没有任何一条生产装配线真正把 RT_DB / Modbus / IEC104 启用起来**，
  只有单元测试在驱动它们。`loop_demo.exe` 仍走默认的 `SimDeviceIO`。
- 设备侧也没有真实进程写点表，目前靠 `set_device_pump()` 模拟。

### 2.2 告警能力在「现场」是缺失的

`10/src/sim_24h.h` 的 `AlarmEntry` + `collect_alarms()` **告警组装寄生在仿真装配层**
（入参是 `Sim24hConfig`）→ **现场部署后系统没有告警能力**。
`06/state_machine.h` 的 `StateEvent` 只有状态迁移，**没有等级 / 事件码**；
`06/` 的 `history()` **只在内存中保留、未持久化**。
P2 的 `SoeLog` 是目前唯一可用的告警载体，但还没有接进生产装配线。

### 2.3 没接过真硬件

TCP 传输层验证止于 **127.0.0.1 回路 + 独立线程服务端**（T51~T57）。
**从未接过真 PCS / 真电表 / 真调度**。且：

- **断链只上报 FAULT，不自动重连**（没有重连状态机、没有主备双链路切换）；
- **无 TLS**（P3 的 §8 明确列出 `TLS / IEC 62351 认证` 未做）；
- **无冗余双网、无 SNTP 对时、无 FTP 定值下发**；
- **Modbus 只实现 TCP，没有 RTU（串口）**；
- **无性能压测**（没有吞吐/时延基准，没有硬性 SLA 断言）。

### 2.4 无界面、无部署

- **没有任何 UI 雏形**（全项目零 `httplib` / `WinMain` / `Qt` / `imgui`）。
  唯一的 HTML 先例是 `10/src/sim_report.h`（561 行，手写 HTML + 内联 SVG，单文件离线可看）。
- **没有部署产物**：没有服务化 / 守护进程 / 开机自启 / 日志轮转 / 配置落盘位置约定。

#### 11.1 补生产装配线（把 RT_DB 真正启用）★ 第一优先

**目标**：让 `EmsRuntime` 在一个真实入口里通过 `RtDbDeviceIO` 跑起来，而不是只在测试里。

**为什么必须先做**：这是 §2.1 的缺口。没有这一条，后面所有联调都无从下手 ——
你无法「联调」一个没有生产入口的系统。

**已有基础**：`RtDbDeviceIO` + 30 点点表 + 初始化器 + 519 断言已就绪（`07/src/rtdb/`），
`attach_device()` 是唯一的介质切换点。

**具体步骤**：
1. **新建 `11/` 模块**（与 `01`–`10` 同构：`src/ tests/ docs/ scripts/`），
   在其中写生产入口（不要改 `07/src/main.cpp`，那是演示程序，保持它的可复现性）。
2. 入口里按这个顺序装配：
   ```cpp
   ems_rt_db_setup();                    // ① 初始化器必须最先跑（reset 会 memset 整个段）
   rt_db_handle_t* h = rt_db_open(...);  // ② 一个进程一条连接
   RtDbDeviceIO dev(h);
   EmsRuntime rt;
   rt.attach_device(&dev);               // ③ 唯一切换点
   rt.apply_configs();                   // ④ 顺序敏感，用 P1 的 apply_config()
   while (running) rt.step(0.1);         // ⑤ 10 Hz
   ```
3. 参数从 P1 的配置文件读（`P1` 的 `apply_config()` 已把 3 处隐式顺序依赖收进一个函数，
   **不要绕过它手写装配顺序**）。

**涉及文件**：新建 `11/src/main_site.cpp`（或类似）；复用 `07/src/rtdb/*`、`P1/src/*`。

**验收标准**：同一段环境脚本下，新入口与 `07/tests/test_rtdb_device_io.cpp` 的
**T26 同口径**（逐拍差异 0 拍）；且 `build_all.bat` 新增一步、断言总数只增不减。

**风险 / 必知的 3 个坑**（都在 `MEMORY.md` 里有记录）：
- **Windows 段存活**：段是页面文件映射对象，最后一个句柄关闭即销毁 →
  初始化器必须保留只读存活句柄，**不能做成「跑完就退」的短命进程**（Linux 无此约束，极易漏）。
- **`reset` 会 memset 整个段**（段级连接计数被清零）→ 初始化器必须在所有连接之前跑。
- **一个进程一条连接**（create/open 共用进程级全局句柄）→ 适配器借用 `rt_db_handle_t*`。

#### 11.2 独立设备进程

**目标**：把目前靠 `set_device_pump()` 模拟的「设备侧」做成**真独立进程**。

**具体步骤**：用 `RtDbPointWriter`（只写 `MEAS/STA/CFG`）写一个设备模拟进程，

#### 11.3 通信接入真实端点 + 断链演练

**目标**：把 `set_endpoint(host, port)` 指向**非 127.0.0.1** 的对端。

**为什么**：TCP 传输层只证明「能过内核」，没证明「能跟现场设备对话」。
现场一定会撞上：点表不一致、UnitId 不符、IOA 分段不同、分帧超时。

**具体步骤**：
1. 南向：用 **Modbus 从站模拟器**（先软件，后真 PCS）验证 `ModbusDeviceIO`。
2. 北向：用 **104 主站测试工具**（先软件，后真调度）验证 `Iec104DeviceIO`
   的 STARTDT / 总召唤三段式 / 周期上送。
3. **断链演练**：拔网线 → 采集不可信 → FAULT → 指令归零 → 门控；
   恢复 → 停 READY，**不自动带载**（这条是安全规程，不是缺陷）。

**验收标准**：断链/恢复的时序与 `P3/tests/test_tcp.cpp` T57 同口径；
且**现场点表逐点核对**有记录（点名、单位、量程、寄存器/IOA 地址）。

**风险**：单次采集失败**不应**进 FAULT（丢一帧只让 `quality_ok_=false` 一拍），
FAULT 需 `data_invalid` **持续**成立 —— 测试要持续断链并**扫描日志找首个 hold_last 位置**，
不能断言固定拍数。

### 3.5 现场工程欠项（不在原 12 周计划里，但上现场一定撞到）

这些不是「优化」，是**不做就上不了现场**的项。按紧急度排：

| # | 项 | 现状 | 要做的事 | 影响 |
| --- | --- | --- | --- | --- |
| 1 | **断线自动重连 + 主备双链路** | 断链只上报 FAULT，**不重连** | 加重连状态机（退避）、双网卡主备切换 | 现场一次抖动就要人工复位 |
| 2 | **SNTP 对时** | 无 | 全站时钟一致，否则 SOE 时间戳不可信 | P2 的 SOE、`06/history()`、经济性核算全靠时间 |
| 3 | **冗余双网** | 无 | 双网口热备 | 现场网络单点 |
| 4 | **TLS / IEC 62351 认证** | 无 | TCP 之上加密 + 调度侧认证 | 调度接入的合规要求 |
| 5 | **Modbus RTU（串口）** | 只做 TCP | `modbus_codec.h` **已含 CRC16**，只需补一个 Transport，适配器不用改 | 老站的电表/PCS 常是串口 |
| 6 | **FTP 定值下发** | 无 | 调度侧的定值文件通道 | 调度接入的配套 |
| 7 | **性能压测** | 无 SLA | 吞吐 / 时延基准，定硬指标 | 周期 12 的「性能」维度无基础 |

## 6. 接手人必读的 8 条纪律与坑（从项目记忆浓缩）

1. **`.bat` 坑两条**：不能从 Git Bash 直接跑（含括号路径）；必须 CRLF 且防「吞 CR」。
   —— 见 §0.3，两条都**静默失败、退出码为 0**。
2. **跨模块 `#include` 是扁平的**（`#include "xxx.h"` 不带路径），靠 `-I` 解析。
   因此**搬头文件到别的模块不用改任何 include**，只需给该模块配好 `-I`。
3. **同一文件的多次编辑必须串行。** 同一批里对同一文件发多个编辑会**相互覆盖** ——
   每个都报成功，但只有最后一个真正留下（实测 9 个编辑只生效 2 处）。
   批量替换优先用**单进程脚本**一次完成，并在末尾断言目标字符串剩余数为 0。
4. **批量改数字必须带边界。** 把页脚 `"20 / 22"` 换成 `"20 / 29"` 时，
   正文里的 `"220 / 220 拍"` 也被改了（前者是后者的子串）→ 变成「220 / 290 拍」。
   用正则 `(?<!\d)20 / 22(?!\d)`，**并在改完后回头断言原始口径串还在**。
5. **改公共契约用「只读视图」，不要改公共结构体。**（§0.5 第 3 条）
6. **`execute()` 的返回值不可信。** 真实设备里它只是「把指令发出去」，
   实际值要等**下一拍** `read_snapshot()`。闭环一律以量测为准。
   —— 这条写进了 `04/src/device_io.h` 的接口注释，别误用。
7. **区间矛盾 ≠ 紧急。** 满充 + 光伏大发 + 不许倒送 → 本拍无可行非零功率 →
   应映射 **DERATED（可自恢复）**，**绝不能锁存 EMERGENCY**。
   早期版本锁存导致 24h 里储能**有 11 小时丧失调节能力**。
8. **故障后不自动带载是安全规程，不是缺陷。** 验收时一定会被问到，先把立场立住。
