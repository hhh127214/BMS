## 三、查出并已修（3 个）

### 3.1 ★ 协议栈把 `GetTickCount64` 当 32 位用 —— 每 49.7 天出错一次

`vendor/lib60870/build.bat` 没定义 `_WIN32_WINNT`，MinGW 按 Win2000 头文件裁剪，
`GetTickCount64` / `inet_pton` / `inet_ntop` 变成**隐式声明**（假设返回 `int`）。
编译期只有一条 `warning:`，运行期却按 32 位处理：

```c
// src/hal/time/win32/time.c —— 正是 104 的 t1/t2/t3 计时底
Hal_getMonotonicTimeInMs() { return (msSinceEpoch)GetTickCount64(); }
```

`GetTickCount64` 数的是**开机以来**的毫秒。截断成低 32 位后每 **49.7 天**回绕一次，
那一刻 `now - last` 变成一个巨大的数 ⇒ t1 立即超时、连接被断。

**修**：编译加 `-D_WIN32_WINNT=0x0601`（只改构建参数，不动 vendor 源码）。
验证：`time.c` 零告警，`socket_win32.c` 的 `inet_pton/ntop` 告警消失，P3 测试仍 **551/0**。
**提醒**：这个故障只在"机器连续开机 50 天以上"出现，实验室永远复现不了。

### 3.2 静态目录穿越：只判 `startswith(root)` 挡不住前缀相同的兄弟目录

```python
full = os.path.normpath(os.path.join(root, rel))
if not full.startswith(os.path.normpath(root)):   # ← 旧
```

`root = ...\15` 时，`...\15_backup\secret.txt` **也**以 `...\15` 开头。
现场建个备份目录 `15_bak` 是常规操作，这条就成了读站点根之外任意文件的口子。

**修**：`full != root_n and not full.startswith(root_n + os.sep)`。
判据 `14/tests/selftest.py [M]`：真起服务发 `GET /../srvo-x/secret.txt`，
断言 **403 且 body 不含密文**，同时同目录正常文件仍 200。

### 3.3 模拟源按钮在飞期间可点 —— 一次操作落 5 条审计

拉链路要 5~10 s，按钮全程可点。用户看没反应就连点，实测**同一秒 5 条一模一样的
「启用模拟源」审计**（后 4 次因链路锁早就返回，所以几乎同时结束）。
不致命（`start` 幂等），但审计里 5 条相同记录会让看日志的人以为点了 5 件不同的事。

**修**：`act()` 加 `busy` 闸门 + 在飞期间禁用三个按钮，结束后**按角色**恢复
（恢复成"全部可点"等于把 viewer 也放开）。判据 3 条。

## 四、查出来但**没动**的（按严重度）

### 阻塞

| # | 问题 | 说明 |
| :--- | :--- | :--- |
| S1 | **GPL-3.0** | `P3/` 静态链接 `lib60870`（GPLv3）。要么整体按 GPL 发布，要么买商业授权。已有 `docs/规划/GPL-3.0-授权决策说明.md`，**需商务/法务定** |

### 高（上现场前必须解决）

| # | 问题 | 证据 / 影响 |
| :--- | :--- | :--- |
| S2 | **平台里没有"改口令"的入口** | `auth.set_password()` 是**死代码**，无端点、无界面、无脚本。而 `14/docs/README.md:315` 写着"现场部署前必须改掉三个默认口令"——**这条要求目前做不到**，只能手工算 PBKDF2 再写库 |
| S3 | **登录失败无任何限制** | `h_login` 只写审计，不限次数、不锁定、不延迟。可离线字典爆破；等保 2.0 三级要求"登录失败处理"（限制次数、结束会话、自动退出） |
| S4 | **口令策略过弱** | 只校验 `len >= 6`，无复杂度、无定期更换、无首次登录强制修改。默认口令 `admin123` 直接可用 |
| S5 | **明文 HTTP** | 口令与 token 在链路上是明文（`16/` 有 SChannel 客户端，但服务端未启用 TLS） |

### 中

| # | 问题 | 说明 |
| :--- | :--- | :--- |
| S6 | **token 走 URL 查询参数** | `api.js` 每个请求都 `?token=…`。会进浏览器历史、代理日志、Referer（CWE-598）。服务端已支持 `Authorization: Bearer`，但 CSV 下载走 `<a download>` 只能靠查询串 —— 要么下载改 fetch+Blob，要么只对下载保留 |
| S7 | **104 从站不校验对端 IP** | `on_conn_request` 直接 `return true`（源码里留着 TODO）。现场应靠纵向加密装置/防火墙兜底，但软件侧没有白名单 |
| S8 | **静态根包含 `15/tests/`** | `_tok_login.html?t=...` 可被任何人当跳板，把任意 token 写进访客浏览器（登录 CSRF）。生产部署应把 `tests/` 排除在静态根外 |
| S9 | **审计日志无防篡改、无保留期** | 表可被任何拿到库文件的人改；无轮转/归档。等保要求审计记录保护 + 留存 ≥6 个月 |
| S10 | **没有备份/恢复** | 只有 CSV 导出。库已 38 MB、`14/data/live/` 49 个 CSV，**都没有保留策略**，长期跑会一直长 |

### 低 / 协议细节

| # | 问题 | 说明 |
| :--- | :--- | :--- |
| S11 | 104 `t0 = 10 s` | 库默认，IEC 60870-5-104 推荐 **30 s**。只影响建链超时；若调度方按标准配置，需显式 `CS104_Slave_setAPCIParameters` |
| S12 | 未发 `M_EI_NA_1`（初始化结束） | 标准要求被控站在初始化完成后上送；部分主站不敏感，但联调时容易被问 |
| S13 | 对时只记录不执行 | `on_clock_sync` 记下时间与原文，但不调系统时钟。现场应由北斗/NTP 统一对时，需在作业指导书里写明 |
| S14 | 采集器一次只连一台 | `active.conn` 单台文件 + `07/ --device modbus` 单目标。6 台设备只采 1 台，这是架构边界，不是故障（面板已写明） |
| S15 | 编译告警 5 条（vendor） | 未用变量、`#pragma comment`、同名宏重定义 —— 均无害，不改上游 |

## 五、行业标准符合性（软件侧自查）

> 判据是**代码与实测行为**，不是实验室测评结论。

| 标准 | 结论 | 依据 / 差距 |
| :--- | :--- | :--- |
| **IEC 60870-5-104** | **基本符合** | APCI：`k=12 / w=8 / t1=15s / t2=10s / t3=20s` 均为标准推荐值；ASDU：`COT=2 / CA=2 / IOA=3`；总召 `C_IC_NA_1` 带 ACT_CON/ACT_TERM、遥控过安全层、CP56Time2a 时标。<br>差距：`t0=10s`（推荐 30）、未发 `M_EI_NA_1`、无 IP 白名单 |
| **Modbus TCP** | **符合** | MBAP 事务号/长度、`unit_id`、功能码 03/04/06/16、异常码 01/02/03 齐全；测试含**半包注入**（按 MBAP.Length 循环读齐） |
| **DL/T 645-2007** | **符合** | `68 A0..A5 68 C L DATA CS 16`，数据域 `+0x33` 只在收发边界做一次，校验和覆盖 `68..DATA`，`FE` 唤醒前导可配 |
| **GB/T 36572-2018**（电力监控系统网络安全防护导则） | **部分符合** | 已做：最小权限三角色、审计、默认同源（CORS 关）、口令 PBKDF2。<br>缺：双因素、通信加密、入侵检测、IP 白名单 —— 多数需现场配合"安全分区/纵向加密"落地 |
| **GB/T 22239-2019 等保 2.0（三级）** | **部分符合** | 身份鉴别：✗ 无双因素、✗ 无登录失败处理、✗ 口令策略弱；访问控制：✓；安全审计：✓ 有，✗ 无保护/留存；数据完整性：部分 |
| **IEC 62443-3-3 / 4-2** | **未评估** | 未做安全等级（SL）划分与认证；本次只做代码级风险梳理 |
| **GB/T 34120 / 36547 / 36276** | **不适用（软件层）** | 是 PCS/储能系统/电池的**设备**要求，软件只能通过点表映射体现，不能靠代码"符合" |
| **IEC 61850** | **不适用（本项目未实现）** | 若站控层要求 MMS/GOOSE，需另做；当前上端是 104 |

**一句话**：**协议的三条主线（104 / Modbus / 645）是认真做的**，帧格式、异常码、时标、
半包、校验这些"联调时才会暴露"的地方都有判据守着；**弱的是"安全合规"这一层** ——
那是产品化要补的，不是协议实现的问题。

## 六、上现场前必须做的 5 件事

1. **补"改口令"能力**（S2）：至少一个 CLI（`python scripts/set_password.py`），最好加
   「我自己的口令」页面 + 管理员重置。**否则文档里那句"必须改口令"是一句空话。**
2. **定 GPL 路线**（S1）：商用授权 or 整体 GPL，二选一，法务出结论。
3. **登录失败处理 + 口令策略**（S3/S4）：失败 N 次锁定/延迟、口令 ≥8 位含三类字符、
   首次登录强制改。
4. **通信加密**（S5）：至少"平台 ↔ 浏览器"上 TLS；104 侧按现场要求走纵向加密装置。
5. **备份与留存策略**（S10）：库定期备份 + `live/*.csv` 保留天数 + 审计留存 ≥6 个月。
