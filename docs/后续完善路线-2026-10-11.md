## 0. 先说公道话：这个项目强在哪（完善 ≠ 补烂摊子）

断言纪律（16K+ 基线、四口径、篡改即红）、界面诚实性（模型源标注、假入口不开）、
CHANGES.md 演进记录、自检自带反证 —— 这些在同类项目里是**少见的强**。
所以下面的"完善"大多是**集成与运维**问题，不是已建成部分的质量问题。
一句话概括现状：**零件造得好，几根总装线没接；能演示，还不能值守。**

## 4. 第 3 层 · 产品纵深：天花板在哪（架构决策，不是补丁）

1. **单柜单簇硬编码**：`07/src/plant_model.h` 是单 PCS（200/200 kW）+ 单电池
   （1000 kWh）的标量配置模型，无簇/柜概念。多柜扩展要同时动点表（17/）、
   模型（07/）、调度仲裁 —— **这是"要不要支持多柜"的产品决策，先决策再动手**。
2. **典型日重复**：sim kinds 实测支持 day/week/month（`simrun.KINDS`），但多日
   = 典型日回绕（界面已如实标注）；**没有真实日历/气象/负荷曲线输入口**。
   S08 预测优化吃的是"已知典型曲线"，不是真预测。接真曲线需要定义数据导入契约。
3. **电价与市场信号**：典型日分时电价；无现货价、无需求响应信号接入。峰谷套利
   模式的 KPI 在真实市场里会失真。
4. **前端 e2e**：`15/tests/e2e_probe.html` 未自动化；自检（327 条）再强也证明不了
   "浏览器里真的渲染出来了"。

## 6. 总优先级（我的判断与理由）

```
第 0 层（1~2 天）   —— 地基。数字不收口，一切验证都在漂移
   ↓
1.2 告警接线 + 2.1 口令 + 2.2 保留策略（并行，各 ~半天~1 天）
   —— 一个补集成、一个拆安全雷、一个拆膨胀雷，互不阻塞
   ↓
1.1 设备侧桥接（先验证再投人，半天验证 + 2~3 天实现）
   ↓
1.3 控的闭环（在 1.1 之上）→ 1.4 分支与上行（先决策）
   ↓
第 3 层（多柜 / 真曲线 / 市场信号）—— 等产品决策，不是工程自发能推动的
```

**为什么这么排**：第 0 层是"验证能力"的前提；1.2/2.1/2.2 是三条独立的短链，
并行做互不阻塞；1.1 是价值最大但最贵的，所以放在地基稳了之后、且先用半小时
验证"采到了但确实进不了库"再投人；第 3 层每一条都是产品方向决策
（要不要多柜？要不要接真市场？），工程侧不该自作主张先动工。
