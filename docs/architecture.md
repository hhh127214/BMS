# 工商业储能 EMS 调控策略设计方案

## 一、项目概述

### 1.1 项目名称

工商业储能 EMS 能量管理与智能调控系统。

### 1.2 项目建设目标

建设一套面向工商业用户侧储能场景的 EMS（Energy Management System），实现对：

- 电网
- 光伏
- 工商业负荷
- 储能电池
- PCS 储能变流器
- BMS 电池管理系统
- 电能表
- 消防及温控系统

进行统一监测、状态分析、功率协调和经济优化。

系统最终实现：

1. 峰谷套利；
2. 削峰填谷；
3. 需量控制；
4. 光伏消纳；
5. 防止反向送电；
6. 电池 SOC 优化；
7. 电池寿命保护；
8. PCS 功率协调；
9. 异常状态保护；
10. 多策略自动切换；
11. 运行数据记录与分析；
12. 收益统计；
13. 远程监控；
14. 策略配置；
15. 后续接入电力市场和辅助服务。

---

# 二、总体设计思想

本系统不采用单一的“定时充放电”策略，而采用：

> **安全约束 + 状态感知 + 多目标优化 + 分层控制 + 策略仲裁**

五个核心思想。

系统的基本控制逻辑为：

```text
                  ┌──────────────────────┐
                  │       云平台/监控平台    │
                  └──────────┬───────────┘
                             │
                    运行数据/策略/指令
                             │
                  ┌──────────▼───────────┐
                  │       EMS 主站         │
                  │                      │
                  │ 状态估计              │
                  │ 策略管理              │
                  │ 功率预测              │
                  │ 优化调度              │
                  │ 安全约束              │
                  │ 策略仲裁              │
                  └───────┬───────┬──────┘
                          │       │
                  ┌───────▼───┐ ┌─▼────────┐
                  │ PCS控制接口 │ │ 电表/负荷 │
                  └───────┬───┘ └──────────┘
                          │
                     充电/放电功率
                          │
                  ┌───────▼───────┐
                  │     电池系统     │
                  │ BMS + 电池簇    │
                  └───────────────┘

       光伏 ─────────────┐
                         │
       电网 ─────────────┼─── 工商业负荷
                         │
       储能 ─────────────┘
```

EMS 不直接负责电池单体保护。

正确的职责划分应该是：

> **BMS 管电池安全，PCS 管功率变换，EMS 管能量调度。**

# 五、核心功率关系

EMS 最重要的一个功率平衡关系：

\[
P_{grid}=P_{load}-P_{pv}+P_{charge}-P_{discharge}
\]

也可以定义储能功率：

\[
P_{ess}=P_{discharge}-P_{charge}
\]

则：

\[
P_{grid}=P_{load}-P_{pv}-P_{ess}
\]

其中：

- \(P_{grid}\)：电网功率
- \(P_{load}\)：负荷功率
- \(P_{pv}\)：光伏功率
- \(P_{ess}\)：储能输出功率

因此：

### 储能放电

\[
P_{ess}>0
\]

会降低电网购电功率。

### 储能充电

\[
P_{ess}<0
\]

会增加电网购电功率。

这就是整个 EMS 功率调控的基础。

# 六、EMS 控制周期设计

EMS 不应该采用：

```c
while(1)
{
    control();
    sleep(1000);
}
```

作为唯一控制机制。

推荐采用：

```text
实时数据采集周期：100~500 ms

设备状态刷新：500 ms~1 s

EMS快速控制周期：1 s

经济调度周期：1~5 min

日前优化周期：15 min~1 h

报表统计周期：5 min~1 h
```

形成：

```text
              EMS
               │
      ┌────────┼─────────┐
      │        │         │
     快环      中环       慢环
      │        │         │
    100ms~1s   1~5min    15min~24h
      │        │         │
    安全控制   实时优化   计划调度
```

# 七、核心策略一：峰谷套利

## 7.1 基本思想

低价时充电：

\[
P_{charge}>0
\]

高价时放电：

\[
P_{discharge}>0
\]

例如：

```text
谷时
00:00 ───── 07:00
       ↓
     充电

平时
07:00 ───── 10:00
       ↓
     保持

峰时
10:00 ───── 12:00
       ↓
     放电

平时
12:00 ───── 17:00
       ↓
     保持

峰时
17:00 ───── 21:00
       ↓
     放电

谷时
21:00 ───── 24:00
       ↓
     充电
```

但是实际系统不能简单按照时间表执行。

必须同时考虑：

- 当前 SOC
- 明日峰时需求
- 当前负荷
- 光伏预测
- 电价
- 电池 SOH
- PCS 限制
- 电池温度
- 最大充放电功率

---

# 八、核心策略二：削峰填谷

峰谷套利解决的是：

> “什么时候充电、什么时候放电？”

削峰策略解决的是：

> “到底放多少？”

设定目标功率：

\[
P_{target}
\]

当：

\[
P_{grid}>P_{target}
\]

启动储能放电。

目标：

\[
P_{grid}\rightarrow P_{target}
\]

因此：

\[
P_{ess}=P_{grid}-P_{target}
\]

例如：

```text
目标需量 = 800 kW

当前负荷 = 1200 kW
光伏 = 100 kW

实际电网功率：

1200 - 100 = 1100 kW

需要储能：

1100 - 800 = 300 kW

EMS：

储能放电 300 kW
```

最终：

```text
电网 = 800 kW
```

---

# 九、核心策略三：需量控制

这是优秀工商业 EMS 和普通“峰谷套利系统”的重要区别。

系统需要实时计算：

```text
当前最大需量
预测需量
目标需量
剩余可调节时间
当前SOC
可用储能容量
```

建立：

\[
P_{demand,pred}
\]

如果预测：

\[
P_{demand,pred}>P_{demand,target}
\]

则提前放电。

例如：

```text
目标需量：1000 kW

当前：
Pgrid = 920 kW

但是预测未来10分钟：
Pgrid = 1150 kW

EMS不能等到1150 kW再处理。

应该提前：

放电 100~200 kW

使：

Pgrid ≈ 1000 kW
```

---

# 十、核心策略四：光伏消纳

当：

\[
P_{pv}>P_{load}
\]

产生多余光伏：

\[
P_{surplus}=P_{pv}-P_{load}
\]

EMS 优先：

```text
光伏
 ↓
负荷
 ↓
储能
 ↓
允许情况下上网
```

因此：

\[
P_{charge}=
\min(P_{surplus},P_{charge,max})
\]

如果储能已经充满：

```text
SOC >= SOCmax
```

则：

```text
负荷 ← 光伏

剩余光伏
    ↓
并网 / 限发
```

---

# 十一、核心策略五：防逆流

如果用户侧不允许向电网反送电：

设：

\[
P_{grid,target}\geq0
\]

当：

\[
P_{grid}<0
\]

说明发生反送电。

EMS 应立即：

### 第一优先级

增加储能充电：

\[
P_{charge}\uparrow
\]

### 第二优先级

降低光伏输出。

### 第三优先级

进入限发状态。

例如：

```text
光伏：1000 kW
负荷：500 kW
储能充电：300 kW

电网：
500 - 1000 + 300
= -200 kW
```

发生逆流。

EMS 调整：

```text
储能充电 → 500 kW
```

则：

```text
Pgrid = 0
```

---

# 十二、核心策略六：电池寿命保护

不能为了套利让电池无限制循环。

EMS 应设置：

```text
SOCmin
SOCmax
SOHmin
最大充电功率
最大放电功率
最大C倍率
温度限制
每日循环次数
累计吞吐量
```

推荐初始策略：

```text
正常SOC范围：

10% ~ 90%

经济运行SOC：

20% ~ 85%

异常状态：

限制充放电

严重异常：

禁止充放电
```

实际项目应根据电芯厂家、系统额定参数及质保条件最终确定。

---

# 十三、核心策略七：SOC 动态管理

不能简单设置：

```text
SOC < 20% → 充电
SOC > 80% → 停止
```

而应该使用动态 SOC Reserve。

例如：

### 第二天预计峰时负荷较大

提高最低 SOC：

\[
SOC_{reserve}=40\%
\]

### 第二天预计峰时负荷较小

可以降低：

\[
SOC_{reserve}=20\%
\]

### 光伏预计第二天很强

可以适当降低夜间保留 SOC。

因此：

\[
SOC_{reserve}=f(
负荷预测,
光伏预测,
电价,
天气,
设备状态
)
\]

---

# 十四、核心策略八：多目标优化

优秀 EMS 的核心不是“规则越多越好”，而是最终应该建立一个优化问题。

目标函数：

\[
J=
\alpha C_{electricity}
+\beta C_{demand}
+\gamma C_{battery}
+\delta C_{curtailment}
+\epsilon C_{risk}
\]

其中：

### 电费成本

\[
C_{electricity}
\]

### 需量成本

\[
C_{demand}
\]

### 电池寿命成本

\[
C_{battery}
\]

### 光伏弃电成本

\[
C_{curtailment}
\]

### 安全风险成本

\[
C_{risk}
\]

最终目标：

\[
\min J
\]

也就是说：

> **EMS 不是追求“电池使用最多”，而是追求“综合收益最大”。**

# 十五、推荐的调度算法

第一阶段：

### Rule-Based

适合快速落地。

```text
if 故障:
    停止

else if 消防异常:
    停止

else if SOC过低:
    禁止放电

else if SOC过高:
    禁止充电

else if 防逆流:
    优先充电

else if 需量超限:
    优先放电

else if 峰时:
    放电

else if 谷时:
    充电

else:
    保持
```

---

第二阶段：

### 优先级策略

建立：

```text
L0 安全保护
L1 电网约束
L2 需量控制
L3 光伏消纳
L4 峰谷套利
L5 电池寿命优化
L6 收益优化
```

优先级：

\[
L0>L1>L2>L3>L4>L5>L6
\]

---

第三阶段：

### MPC 模型预测控制

建立未来：

```text
未来24小时负荷
未来24小时光伏
未来24小时电价
未来SOC
```

预测未来：

\[
P_{load}(t)
\]

\[
P_{pv}(t)
\]

\[
Price(t)
\]

然后每5~15分钟重新优化。

形成：

```text
预测
 ↓
优化
 ↓
执行未来一小段
 ↓
重新采集数据
 ↓
再次预测
 ↓
再次优化
```

这就是 MPC 的基本思想。

# 十六、策略仲裁器设计

这是整个 EMS 软件最重要的模块之一。

多个策略可能同时产生冲突。

例如：

```text
峰时
      ↓
套利策略：放电500kW

但是：
SOC = 18%
      ↓
SOC策略：只能放电100kW

同时：
电网需量：超限
      ↓
需量策略：需要放电300kW

同时：
PCS最大放电：
250kW
```

最终不能简单选择某一个策略。

应该：

```text
套利策略
   ↓
需量策略
   ↓
SOC约束
   ↓
PCS约束
   ↓
安全约束
   ↓
最终指令
```

最终：

\[
P_{cmd}=
\operatorname{clip}
(P_{strategy},
P_{SOC},
P_{PCS},
P_{grid},
P_{thermal},
P_{safety})
\]

# 十七、EMS 主控制循环

推荐整体算法：

```text
EMS启动
  ↓
设备初始化
  ↓
读取配置
  ↓
建立设备通信
  ↓
检查设备状态
  ↓
读取实时数据
  ↓
数据质量检查
  ↓
状态估计
  ↓
安全检查
  ↓
预测
  ↓
策略计算
  ↓
策略仲裁
  ↓
功率限制
  ↓
生成PCS指令
  ↓
下发PCS
  ↓
反馈校验
  ↓
记录运行数据
  ↓
进入下一控制周期
```

伪代码：

```c
while (ems_running)
{
    acquire_data();

    if (!data_valid())
    {
        enter_safe_mode();
        continue;
    }

    update_state();

    if (safety_violation())
    {
        emergency_control();
        continue;
    }

    forecast_load();
    forecast_pv();
    update_price();

    strategy_peak_valley();
    strategy_demand_control();
    strategy_pv_consumption();
    strategy_anti_reverse_power();
    strategy_battery_protection();

    power_cmd = strategy_arbitration();

    power_cmd = apply_soc_limit(power_cmd);
    power_cmd = apply_pcs_limit(power_cmd);
    power_cmd = apply_grid_limit(power_cmd);
    power_cmd = apply_temperature_limit(power_cmd);

    send_pcs_command(power_cmd);

    verify_command();

    record_data();

    sleep_until_next_cycle();
}
```

# 十八、故障处理设计

EMS 必须设计状态机。

推荐：

```text
NORMAL
  │
  ├── WARNING
  │
  ├── DERATED
  │
  ├── FAULT
  │
  └── EMERGENCY
```

例如：

### NORMAL

正常运行。

### WARNING

轻微异常。

例如：

```text
温度偏高
SOC偏高
通信偶发丢包
```

### DERATED

降额运行。

例如：

```text
电池温度升高
PCS功率受限
SOC接近边界
```

### FAULT

设备故障。

```text
停止相关设备
```

### EMERGENCY

严重安全事件。

```text
立即停止充放电
切断相关设备
上报消防/保护系统
```

通信服务与策略算法解耦。


# 四十一、项目最终目标

这套 EMS 最终不是一个：

> “到了晚上充电，到了白天放电”的程序。

而应该是一个：

> **能够感知现场状态、预测未来负荷和光伏、理解电价、判断电网需求、评估电池状态，并在安全约束下自动寻找最优运行方案的能源管理系统。**

最终控制目标可以概括为：

\[
\boxed{
\min
\left(
电费成本+
需量成本+
电池寿命成本+
弃光成本+
安全风险
\right)
}
\]

同时满足：

\[
SOC_{min}\le SOC(t)\le SOC_{max}
\]

\[
P_{charge}\le P_{charge,max}
\]

\[
P_{discharge}\le P_{discharge,max}
\]

\[
P_{grid}\ge P_{grid,min}
\]

\[
T_{min}\le T\le T_{max}
\]

最终实现：

> **安全第一、收益第二、寿命第三、智能优化第四。**

这也是本项目 EMS 的总体设计原则。
