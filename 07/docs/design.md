## 0. 全系统符号约定

| 符号 | 约定 |
| --- | --- |
| `P_bat` | **放电为正、充电为负** |
| `P_grid` | **取电为正、倒送（馈网）为负** |
| `P_load` | 恒 `> 0`（本地负荷） |
| `P_pv` | 恒 `> 0`（光伏发电） |
| 功率平衡 | `P_grid = P_load − P_pv − P_bat` |

由平衡式可把"并网约束"直接翻译成对 `P_bat` 的区间：

```
P_grid ≥ g_min  →  P_bat ≤ (P_load − P_pv) − g_min      （上界）
P_grid ≤ g_max  →  P_bat ≥ (P_load − P_pv) − g_max      （下界）
```

## 3. 周期 7：实时控制闭环（`plant_model.h` + `realtime_loop.h`）

> 设计方案原文："实现毫秒级实时控制闭环，无延迟、无振荡。"

### 3.1 闭环链路

```
电表实时数据 → EMS 算法计算 → 策略仲裁 → 安全约束 → PCS 执行 → 实际功率反馈 → EMS 迭代修正
```

`EmsRuntime::step()` 的 11 步实现：

| 步 | 动作 |
| --- | --- |
| ① | 采集：`plant_.sample(t_)` 产出**冻结**的 `RealtimeSnapshot`（接口规范 §5 强约束） |
| ② | 故障检测：`detect_faults()` |
| ③ | 安全评估：`safety_.evaluate()` → `SafetyVerdict` |
| ④ | 状态机：`fsm_.update()` |
| ⑤ | 协同层：`coord_.update()` → `plan_target` / `coord_target` |
| ⑥ | 策略层：`mgr_.tick()` + 安全结论并入 |
| ⑦ | 仲裁层：`arbiter_.arbitrate()`（L0→L3 区间收敛 + L3 desired 加权） |
| ⑧ | 实时层纠偏叠加（L2 有界修正） |
| ⑨ | **输出整形 → 安全兜底 → 状态门控 → HOLD_LAST** |
| ⑩ | 执行层：`plant_.step()`（PCS 物理响应） |
| ⑪ | 反馈 + 记录：实测功率回灌下一拍快照，形成闭环 |

### 3.2 第 ⑨ 步的顺序为什么重要

```
OutputShaper（死区/滞环去抖） → SafetyEngine::apply()（区间限幅 + 变化率限速）
  → 状态机门控（FAULT/EMERGENCY 强制 0，覆盖一切） → HOLD_LAST
```

- **整形放在最后一级**：`04/` 仲裁器的死区只作用于 L3 的 `desired`，而 L2 实时纠偏是在仲裁**之后**叠加的，因此抖动会绕过仲裁器死区。必须在链路末端再放一道整形。
- **安全层在整形之后**：安全兜底必须无条件生效，不能被整形"软化"。
- **状态机在安全层之后**：FAULT / EMERGENCY 必须能覆盖一切（包括安全层的限幅结果）。

### 3.3 `OutputShaper` 语义

```
|cmd| 持续落在死区内 → 输出 0；一旦越出死区立即跟随。
```

确认期 `switch_delay` 拍用于抑制边界抖动。

> **反例（已修正）**：早期实现里多了一条"同方向死区内沿用上一拍输出"的分支，导致小信号**永远被保持**而不是被清零 —— 死区形同虚设，开关两档结果一模一样。

### 3.4 被控对象 `PlantModel`

按真实物理顺序建模：

```
指令限幅 → 死区队列（pcs_deadtime_s）→ 物理变化率（pcs_ramp_kw_per_s）
  → 一阶惯性（α = 1 − e^(−dt/τ)）→ 硬限幅 → SOC 积分（充放效率）→ 温升模型
```

- **PCS 待机损耗放在负荷侧**：`P_load += pcs_standby_kw`。若从 `P_bat` 扣除，会形成一个**无法补偿的稳态跟踪偏差**。
- 量测噪声（`noise_kw` / `noise_soc`）用于验证控制器与整形的抗噪能力。
- 故障注入：`set_comm_bms/meter/pcs`、`set_pcs_fault`、`set_device_offline`、`set_data_valid`。

### 3.5 验收指标口径（`LoopMetrics`）

| 指标 | 口径 | 判定阈值 |
| --- | --- | --- |
| `mean_err` / `rmse` | `P_actual − P_cmd` 的均值 / 均方根 | — |
| `steady_err` | 末段 10% 的平均绝对误差 | `≤ 15 kW`（`no_lag`） |
| `over_delivery` | `Σmax(0, |P_actual| − |P_cmd|) / Σ|P_cmd|` | `≤ 25%`（`no_lag`） |
| `sign_flips` | 指令穿越零点次数（0.5 kW 死区） | `≤ 0.20/s`（`no_oscillation`） |
| `cmd_reversals` | 指令增量符号反转次数（`dir_eps = 2 kW`） | `≤ 1.00/s`（`no_oscillation`） |
| `cmd_travel` | `Σ|Δcmd|`，输出"抖动总量"的标准度量 | — |
| `max_reverse` / `reverse_duration` | 有效倒送（`P_grid < −5 kW`）的峰值 / 累计时长 | — |

> **为什么用 `cmd_travel`**：`cmd_reversals` 会把"死区造成的 bang-bang 输出"也计入反转，无法反映死区的收益；`Σ|Δcmd|` 才是衡量 PCS 无效往复动作的正确口径。
>
> **为什么 `no_lag` 不含整定时间**：在连续变化的激励下整定时间不具判别力（实测 200 s 只是"指令一直在变"），故仅作参考输出，判据只看稳态误差与超发率。

### 3.6 试验 2：并网点边界抖动的三层治理

激励：净负荷恒为 0，量测噪声 `σ = 3 kW`（关口功率 `σ ≈ 4.2 kW`）。

| 配置 | 指令总行程 | 方向反转 | 大幅跳变 | 无振荡判定 |
| --- | --- | --- | --- | --- |
| ① 基线（无滤波/无死区） | 4548 kW | 809 次 | 266 次 | 不成立 |
| ② + 量测滤波（α=0.05） | 3671 kW（−19%） | 689 次（−14%） | 199 次（−25%） | 不成立 |
| ③ + 量测滤波 + 死区滞环 | 1326 kW（**−70%**） | 183 次（**−77%**） | 185 次（−30%） | **成立** |

结论：**根因在量测侧**（安全边界的基准量带噪声），量测低通滤波是主药，输出死区+滞环是辅药。

## 已知边界与后续工作

- **多机并联**：当前模型是单 PCS；多机场景需在 `SafetyEngine` 之后增加功率分配层。
- **`EmsRuntime` 装配了 `08/` 的协同层**：本模块的闭环头文件 `#include "dispatch_coordinator.h"`，故编译需 `-I ../08/src`。这是**运行时的调用关系**（闭环调用优化层），头文件层面无环 ——`08/src/*.h` 不包含 `07/` 的任何头文件。
- **暂态倒送无法靠变化率消除**：峰值倒送由光伏阶跃瞬间的实际出力决定，与变化率无关；根治需光伏逆变器限功率或提前预留充电裕量（见场景 C 试验 3）。
