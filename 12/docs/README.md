# 12/ — 周期 12：最终验收

> 依据：《工商业储能EMS调控策略设计方案.md》§7 周期 12
> 「完成功能、策略、安全、性能、稳定性、多策略协同、文档全维度验收，
> 正式输出 EMS V2.0 版本。」

本模块是**交付门禁**，不是新功能。它把前面 11 个周期交付的能力按设计方案的
七个维度重新测量一遍，输出一份可复核、可机器判定、可 CI 门禁的验收报告。

---

## 1. 它在整个工程里的位置

```
        01  02  03  04  05  06  07  08  09  10  11      ← 能力交付（周期 1~11）
        └───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
                            │
                            │  只读引用各层**公开出口**，不改动任何模块
                            ▼
        12  ──  七维度验收 ──▶ ACCEPTANCE-REPORT.{md,json,html}
                                  │
                                  └──▶ 退出码：0 通过 / 1 不通过（CI 门禁）
```

`12/` 对上游是**纯消费者**：不新增算法、不修改任何模块、不读私有成员。
因此"验收通过"这句话的含义很明确 —— **被验收的代码就是提交的那份代码**。

### 为什么验收要重新测量，而不是"引用既有测试的结论"

前面 11 个周期的测试是**开发期断言**：断言"我实现的东西符合我的实现"。
验收断言的是"交付物符合设计方案的字面要求"。两者口径不同：

| | 开发期断言（01~11） | 验收断言（12） |
|---|---|---|
| 判据来源 | 实现细节（内部变量、私有状态） | 公开出口（`StepRecord` / 点表 / 文件 / 墙钟） |
| 可复现性 | 需要读源码才能核对 | 报告自带判据+实测，第三方可独立复核 |
| 阈值 | 无（或形如 `>0`） | **可量化的阈值**，且阈值可被现场标定覆盖 |
| 失败含义 | 实现有 bug | 交付物不达标 |

所以本模块**不复用** `01/`~`11/` 的断言，只复用它们的**能力**。

| 维度 | 验收对象 | 检查项 | 证据来源 |
|---|---|---|---|
| **A1 功能** | 策略注册/启停、全链路闭环、状态机七态可达、设备 I/O 三适配器等价、点表自检、配置化往返、日计划装载、**关口功率单一数据源（电表口径）** | 9 | `04/ 06/ 07/ P1/` |
| **A2 策略** | 9 个策略逐个在"触发工况"下核对设计意图（§3.1~§3.9） | 9 | `04/src/strategies_9.h` |

| **A4 性能** | 单拍闭环耗时（均值/峰值/占用率）、24h 离线仿真墙钟加速比、长跑资源无泄漏 | 5 | `07/ 10/` |
| **A5 稳定性** | 24h 长稳（含三段故障窗）、跨进程闭环长稳、采集零 stale、SOE 零丢弃、状态迁移与指令抖动有界、可观测性与 `log_every` 解耦、**BMS 禁充放位通路** | 7 | `07/ 10/ 11/ P2/` |

| | | **55** | |

每条检查项都带三要素：**编号 / 判据（criterion）/ 实测（evidence）**，
报告里两者同时输出 —— 任何一项不通过都能被单独定位与复核。

### 判据阈值的来源

| 检查项 | 阈值 | 依据 |
|---|---|---|
| A4-01 单拍耗时均值 | ≤ 1000 µs | 10 Hz 控制周期下 CPU 占用 ≤ 1% |
| A4-02 单拍耗时峰值 | ≤ 50000 µs | 半个控制周期（首拍含冷启动，实测可达十几 ms） |
| A4-03 时间占用率 | ≤ 20% | 留 5× 工程余量给现场日志/通信开销 |
| A4-05 墙钟加速比 | ≥ 2000× | 24 h 仿真必须能在分钟级跑完（离线寻优迭代用） |
| A5-02 状态迁移次数 | ≤ 30 次 / 24 h | 平均每小时不超过 1.25 次，超出即为抖动 |
| A5-03 指令总行程速率 | ≤ 5 kW/s | 沿用 07/ 的工程口径（翻转 ≤ 0.2/s、反转 ≤ 1.0/s） |

阈值全部集中在 `AcceptanceRunner::Options` 里，现场标定只需要改一处。

## 3. 怎么跑

```bat
REM 编译验收器
12\scripts\build.bat

REM 正式验收（跑七维度 + 落盘三件套报告 + 返回门禁退出码）
12\scripts\run_acceptance.bat

REM 只打印、不落盘；只显示汇总与失败项
12\scripts\run_acceptance.bat --no-write --quiet

REM 缩小规模做快速体检
12\scripts\run_acceptance.bat --perf-steps 3000 --rtdb-ticks 2000

REM 模块自测（T51~T59）
12\scripts\build_test.bat
```

也可直接调用 CLI：

```bat
build\acceptance.exe [--root DIR] [--perf-steps N] [--rtdb-ticks N]
                     [--scenario-scale K] [--no-write] [--quiet]
```

实测耗时（本机，`-O2`）：**全量验收约 4~5 s**，模块自测约 5 s。

## 5. 四个"必须记住"的验收结论

这四条是本项目在验收阶段最容易被误判、也最值得写进交付说明的地方。

### 5.1 区间矛盾 → DERATED，不是 EMERGENCY

满充（禁充，下界 = 0）叠加光伏大发（不许倒送，上界 < 0）时，本拍**无可行非零
功率**。安全引擎把区间收成 `[0,0]`，同时置 `contradiction=true` + `derated=true`，
**不置** `emergency`。

原因是工程性的而非理论性的：`EMERGENCY` 会**锁存**，需要人工复位；一旦锁存，
储能会在整个光伏高发时段失去调节能力。而 `DERATED` 可自恢复。
→ 检查项 **A3-09** 就是这条决策的回归护栏。

### 5.2 变化率不是区间约束

`ramp_rate` 是"相对上一拍已下发指令的邻域限制"，只能做**后置限速器**。
若硬塞进区间求交，冷启动（`p_last = 0`）会把区间收成 `[-20, +20]`，
再与硬安全区间（例如并网要求的 `[42, 250]`）求交即得"下界 > 上界"，
仲裁器误判矛盾 → 指令被迫归零 → 反而突破并网/需量边界。

→ 检查项 **A3-07** 断言 `binds_interval=false` 且 `counts_as_derate=false`。

### 5.3 设备 I/O 三适配器逐拍等价

`SimDeviceIO`（`PlantModel`）/ `MemoryDeviceIO`（进程内点表）/ `RtDbDeviceIO`
（共享内存）在同一指令序列下 **P_bat 与 SOC 逐拍偏差 ≤ 1e-9**（A1-05）。

这是"算法代码零改动就能换设备接口"这句产品化承诺的**量化证据**。
注：比较时需把 `pcs_deadtime_s` 归零、`pcs_standby_kw` 归零 ——
前者只有 `PlantModel` 实现、后者会混入站用电；这是口径问题，不是缺陷。

> **等价性的边界（2026-09-19 补充）**：等价的前提是**限值相同**。三个适配器在
> `limits_are_live()` 上有**能力差异** —— `RtDbDeviceIO → true`（设备侧进程随时
> 可能改 `CFG.*` / `STA.BMS_*_FORBID`），仿真两个适配器 `→ false`。
> 这是**刻意的**：仿真夹具的限值由调用方注入，若每拍被设备侧覆盖，`09/` `10/`
> `P1/` `P2/` 共 8 处注入点全变。所以 A1-05 比的是"限值相同下三个适配器逐拍
> 等价"，**不是**"三者的刷新时机也相同"。

> **★ "等价"不等于"取对了源"（2026-09-19 追加 A1-09）**：缺口 A2 是"关口功率
> 算法路径**推算**、记录路径**读电表**"。修完之后三个适配器仍然逐拍等价 ——
> 但设备侧发布的 `MEAS.P_GRID` **恰好等于**那个相减式，所以**改前改后 A1-05 都过**，
> 等价性本身**没有区分度**。
> 于是补了 **A1-09**：给电表注入 **+40 kW 系统偏差**，断言算法出口取的是**电表**
> （而不是三路相减的平衡值），并给出反向守卫"两源确实差 40 kW"。
> **教训**：等价性只证明"三条路一样"，不证明"三条路都对"。**同一物理量的唯一权威
> 计量点必须单独判一次。**

### 5.4 安全输入型点位：验收口径与开发期口径**必须不同**

A5-07（2026-09-19 追加）是"BMS 禁充放位"这条通路的验收。它与 `11/T48` 同机制，
但**独立编排、独立口径**：

| | `11/T48`（开发期） | `A5-07`（验收） |
|---|---|---|
| 观察对象 | `rec.p_upper` / `rec.p_lower` / `rt.device_limits()` | **公开出口 = 下发指令** `rec.p_cmd` |
| 判据写法 | 极值 + 计数混合 | 纯计数 + 反向守卫（窗内 ≥ 5 拍非门控） |
| 失败含义 | 实现有 bug | 交付物不达标 |

**为什么"事件型通路"不能用末态验证**：置 1 只发生在窗口内。若只看末态，
「通路断了」与「窗口过去了」**完全不可区分** —— 判据会恒过。所以两条测试
都**边跑边采**，再用"窗内 vs 窗外"的差分来取得区分度。

**差分判据必须排除的两条"设计内"路径**（否则没有区分度）：

- `state_gated`：非运行态时区间被收到 `0`（不是禁放造成的）；
- `hold_last`：采集超时保持时，区间**钉在上一拍指令**上（单点）。

实测口径：`禁放拍数=99（窗内 100 拍）/ 窗外残留=1 / 窗内 p_upper≤0 拍数=98
vs 窗外常规拍 1`。

## 6. 已知限制

1. **A6 场景是"抽样工况"而非真实日曲线**。7 个场景的环境脚本是常数或正弦，
   用于暴露策略耦合缺陷（这正是指标所需）。真实日曲线的经济性验收在
   `10/` 的 24h 离线仿真里（A4-05 顺带跑了它并核对了经济净收益）。
2. **A4 的性能数据受机器影响**。绝对值（µs）会随 CPU/负载变化，
   判据用的是"占控制周期的比例"而非绝对数，跨机可比。
3. **A7 只验文档"存在且非空"**，不验文档内容质量。内容质量靠评审，
   不靠脚本 —— 脚本能做的只是让"忘了写文档"这件事无法悄悄发生。
4. **`12/data/_report_selftest/`** 是 A7-06 的自检产物（验证渲染+写盘可用），
   可以随时删除，会自动重建。
