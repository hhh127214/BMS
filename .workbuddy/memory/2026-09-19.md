## 2. 联调暴露并修掉 `07/` 的三个真实缺陷

| # | 缺陷 | 表现 | 修法 |
|---|---|---|---|
| 1（严重） | `EmsRuntime::step()` **从不调用 `write_command()`** | 权限区间恒 `[0,0]`，3000 拍里 **2978 拍**被判"指令越界" | `execute()` 之前插入 `io_->write_command(cmd)`；**发布 ≠ 驱动，不可合并** |

## 3. 顺带发现：26 个 bat 脚本的"吞 CR"缺陷

全量构建第一步就 `'the' 不是内部或外部命令`。根因是既有 19 个 bat 为 LF 行尾 +
中文注释触发 CP936 吞 CR（行尾落在双字节前导字节 `0x81–0xFE` 上会把 `\r` 吞掉，
下一行前缀被当命令执行）。**两个坑都静默失败、退出码仍为 0**。

→ 写了 `scripts/fix_bat_encoding.py`（LF→CRLF + 模拟 CP936 扫描越界补空格，幂等，
支持 `--check`），一次性修 26 个文件。**每次新增/改写 bat 后必须跑一次 `--check`。**

### 10.4 Python 模拟器的架构决策（建议走 Modbus TCP 从站）

Python 不能 `#include` C 头文件。三条路：ctypes 调 DLL / 用 mmap 复刻
`SharedMemorySegment` 布局 / **走 Modbus TCP 从站（推荐）**。
理由：模拟器直写共享内存会让"Modbus 写寄存器"这条路在接真机前**一次都没走过**，
所有协议层问题（字节序、寄存器地址、写后回读、超时重试）都会在现场第一次遇到。
且 (c) 把"跟别人对接"也一并铺好 —— 同一个 `ModbusDeviceIO`，
对模拟器是调试，对真机是生产。

### 11.2 四条必须记住的库行为（照手册写就会错）

1. **GI 的 ACT_TERM 必须带一个信息对象** —— 空 ASDU 的 TypeID 是 0，
   主站侧 `createFromBufferEx` 校验失败直接丢帧 → 主站永远等不到终止 → 周期性重召。
   从站侧看着"总召一直有请求"，像主站有病。官方 `examples/cs104_server/simple_server.c`
   装了 `InterrogationCommand_create(NULL, 0, qoi)`，**手册 §6.4/§6.9 漏了这一步**。
2. **CP56Time2a 用 UTC（`gmtime`）**，不做时区换算 → 要显式扳回北京时间。
   坑中坑：库的双向换算**严格互逆**，所以"发出去读回来比相等"的自环测试**永远恒等**，
   差 8 小时也照样过。
3. **从站 t0 默认 10 s**（手册写 30）。
4. **带时标类型没有公开取值接口** —— 主站侧要读值只能 include 内部头
   `information_objects_internal.h` 按结构体读。

### 11.3 ASDU 容量（静默丢点的经典来源）

上限 **249 字节**；带时标短浮点每点 `IOA(3)+值(4)+品质(1)+时标(7)=15`，帧头 6
→ **一帧最多 16 点**（不带时标 30 点）。本项目 18 个遥测不分包会**静默丢 2 个**

### 11.4 本轮修掉的 6 个"静默出错"缺陷

1. **RT_DB 品质常量镜像写反**（`kRtdbQualityGood = 0`，真值 `1`）→ **24 个点品质全 `0x80`**、
   值全对、协议层无异常、单元测试全绿、调度画面全灰。
   修法三层：① 不抄数字（`rtdb_quality.h` 直接引用 `QUALITY_GOOD`）
   ② `static_assert` 编译期对账 ③ **端到端外部真值对账**（日志里 `0x80` 必须 0 条）。
2. **`rt_db_structs.h` 的 C11 原子宏破坏 libstdc++**：它把 `atomic_store_explicit` /
   `atomic_thread_fence` 定义成**函数式宏**，而函数式宏匹配**不看命名空间限定** →
   `std::atomic_thread_fence(...)` 这些**声明**被就地展开，报错却是
   `expected unqualified-id before 'sizeof'` 且指向该头第 34 行。
   修法：`rtdb_quality.h` **必须排在所有 C++ 标准库头之前**，内部立刻 `#undef` + 加 `#error` 前置检查。
3. **计数自增早于载荷写入** → 观察者按计数判就绪会读到半成品（T66 偶发失败，像随机抖动）。
   规矩：**先写载荷，release fence，再自增计数** —— 计数是"我前面写的东西都好了"的发布信号。
4. **`char raw_dumped_` 溢出**：`char` 到 127 回绕成负 → `> 200` 永不成立 →
   `--dump-raw` 本想只打 200 帧，结果刷满屏。窄类型做计数器要一律查一遍。
5. **ASDU 分包**（见 11.3）。
6. **`P3/scripts/build.bat` 里的 VT 字符（0x0B）**：Python 批量改写时 `"\v"` 被当转义序列，
   `..vendor\` 变成 `..<0x0B>endor\`；因为这条 `-I` 与已有重复，gcc 只发警告就继续，
   **错得毫无声响**。→ 给 `scripts/fix_bat_encoding.py` 加了**控制字符检测**
   （`find_ctrl_chars` + `CTRL_NAMES`，**只报不改**：到底该是哪个字符只有人知道）。

### 11.5 本轮的设计改动：品质三态取代 bool

`IDataSource::read()` 的 `bool* quality_ok` → `Quality*{kGood,kNotTopical,kInvalid}`。
理由：IV(0x80) 与 NT(0x40) 是两件事，压成 bool 必然选一个更差的表达 ——
压向 IV 让主站把"5 秒前的真值"显示成"没数据"，压向 GOOD 让主站拿陈旧值当实时值。
源头本来就有这条信息（RT_DB 的 `QUALITY_UNCERTAIN`），不该在转发层丢掉。

### 11.6 端到端实测基线（**双侧证据**）

阶段 A（设备在线）→ 全 `0x00` GOOD；阶段 B（停设备 + 等 5 s，`--stale-ms 3000`）→ 全 `0x40` NT、
**值冻结在最后一次好值**；`0x80` **0 条**。总召唤 `确认→数据(18+6)→终止` 成对 2/2；
带时标 18 点实拆 **16+2**；命令肯定 2 / 否定 0；时间戳是北京时间。

> 只有 A 全绿不能说明 NT 通路活着，只有 B 全 NT 不能说明 GOOD 通路没被误伤 —— 两侧都要有。

**实测发现的语义边界（不是 bug）**：`CMD.*` 三点在没跑 `ems_side` 时被判 NT ——
正确（该告诉调度"权限区间不可信"），但说明 **`--stale-ms` 不能一刀切**，
要按"最慢的正常更新周期"取；静态配置量若只在启动时写就得调大或关掉。

### 11.7 遗留（已写入 P3/docs/design.md）

① **EXT 点区 6 点**（下行目前无落点；★ `6001` 应映射到**权限区间**而非直接覆盖 `p_desired`，
否则 L0 安全约束对调度指令失效）② 转发表外置 CSV ③ 累计量 BCR（RT_DB 还没有电度点）
④ **BMS 限值无真实来源**（现在只是仿真注入点）⑤ IP 白名单 ⑥ **GPL-3.0 授权路线（需商务/法务）**。

### 11.8 踩到的工具坑（以后别重复）

- **Bash heredoc 会把 `\\` 吃成 `\`**：在 Bash 里跑 Python 时源码中不要出现反斜杠字面量，
  改用 `chr(92)` 拼路径；**更坑的是 `"\v"` 会直接产出 VT 字符（0x0B）**。
  改文件优先**按行号**改而不是长字符串匹配。

## 12. 收尾：全量构建暴露 T47「stale 恒 0」判据缺陷 → 全量 8498 断言全绿

### 12.1 事件

P3 交付后跑 `build_all.bat`：`[BUILD ALL FAIL]`，`EXIT=1`。**不是 P3 的问题** ——
是 `11/` T47 红了一次：

```
FAIL  tests\test_system_integration.cpp:616 : io.stale_reads() == 0
并发读写 1701 点 / 1068810 次 read_snapshot / stale=22
```

同一二进制**单跑恒为 0**（133/133 全绿）。⇒ **这条判据测的是"机器闲不闲"，
不是"代码对不对"。**

### 12.2 根因（三层）

1. `RtDbDeviceIO::refresh()` 的重试是**次数上限**（`kReadRetries=64`）不是**时间上限**；
   无就绪同优先级线程时 `yield()` **立即返回** → 64 次预算在微秒级烧完。
2. 写者临界区含 `update_timestamp()`；写者若被 OS 抢在临界区里，`sequence` 在整个
   时间片（**15.6 ms**）保持奇数 → 这期间读到该点的尝试**必然全部耗尽**。
   全量构建（同时编 29 个组件）正是这种重载场景。
3. **判据本身错**：`stale` 的语义是「保留上次有效值 + 品质置不可信」，是**设计内降级**，
   下游安全层本来就拒绝采信 `quality != GOOD`。**允许非零的设计量不能用恒零断言。**

### 12.3 修法（**刻意不调大 kReadRetries** —— 那只是把假红推远）

- `07/src/rtdb/rtdb_device_io.h`：拆出 `collisions()`（首次即失败 = 真撞上了）/
  `absorbed()`（被重试吸收），恒有 `stale <= collisions`；顺带修掉过期注释
  （注释写"取 8"，代码是 64）。
- `11/` T47 判据四层：①`collisions>0`（反向守卫）②`stale < collisions`（删重试循环就红）
  ③`stale*1000 < reads`（量级）④`bad_soc == 0`（**硬判据**）；
  读循环改成「至少 1.0 s **且**必须撞上过碰撞才收工（上限 3 s）」—— 守卫不能靠概率。
- 同口径修 `11/src/main_ems.cpp` 检查项（改为"降级 ≤ 碰撞的 1%"，并按 `coll0` 扣预热期）
  与 `11/src/integration_runner.h` 报告文案。
- **刻意不动**：`07/` 4 处 + `11/` T41~T45 + `12/` A5-04 的 `stale==0`
  （`device_pump` **同线程顺序**驱动 → 确定性 0，硬判据成立且更强）。

## 17. A1 修复：BMS 禁充放位走不进 RT_DB（+ 连带发现"运行期限值冻结"）

来源：`docs/规划/模拟器与设备接入梳理.md` §10 的缺口 **A1（风险最高的一条）**。
用户批准开工第 1 件。

### 17.1 改了四层

| 层 | 文件 | 要点 |
|---|---|---|
| 点表 | `07/src/rtdb/ems_point_table.h|.c`、`07/src/memory_device_io.h` | 30 → **32 点**；新增 `STA.BMS_CHG_FORBID` / `STA.BMS_DIS_FORBID`，**追加在枚举末尾** |
| 适配器 | `07/src/rtdb/rtdb_device_io.h` | `read_limits()` 原本**硬写 false**，改真读 |
| 运行期刷新（连带） | `04/src/device_io.h`、`07/src/realtime_loop.h` | 新增 `limits_are_live()` 能力开关 + `refresh_limits_each_step` + `step()` ⓪ 步 |
| 断言 | `07/T25`、`11/T48`、`12/A5-07` | 三层、三套独立口径 |

### 17.2 最关键的两个决策

**① 点表只能追加在末尾。** 索引是**运行时坐标** —— 中间插入会让其后所有点整体偏移，
而共享内存里**已有段的索引不跟着变**，现场表现为「点名对得上、值全是隔壁点的」。
追加在末尾则 `0..29` 逐位不变，老段（30 点）与新段（32 点）在前 30 点上继续兼容。

**② 默认值取 0（允许）而不是 1（禁止）。** 默认禁止会让"设备侧尚未上线"直接锁死
`[0,0]`（冷启动不可用）；而"允许"与修复前**逐位一致**，不引入新风险。
fail-safe 由 `05/` 的 `bms_comm_lost → [0,0]` **独立**承担（不依赖本点）。

### 17.3 连带发现（比 A1 本身更严重）

写 T48 时断言红了（`dis_ticks = 0`，200 拍全是 false）→ 追下去发现
**`EmsRuntime::step()` 从不调用 `refresh_device_limits()`** —— 限值只在
`init`/`reset`/`configure_plant`/`attach_device` 里刷，即**装配期刷一次，运行期冻结**。

后果面远超禁充放：BMS 动态降功率、PCS 额定、变压器容量、契约需量**全部退化成装配期常量**。
而 `04/IDeviceIO::read_limits()` 的契约写的是"每个控制周期刷新"。
**注释声称的行为与代码实际的行为不一致** —— 本项目第 N 次栽在同一件事上。

修法（不能无条件每拍刷，`dev_` 有两个写入者）：
`limits_are_live()`（`RtDbDeviceIO → true` / 仿真 → `false`）→ `attach_device()` **自动打开**
`refresh_limits_each_step`（**只打开、不关闭**）→ `step()` ⓪ 步刷新。
**现场装配不会忘，仿真行为逐位不变**（`07/T26` 逐拍差异仍 0 拍）。

### 17.4 判据踩的两个坑（都是"判据错"不是"代码错"）

1. `max_upper_in ≤ 0` 恒红 → 窗内第 1 拍必然读到**上一拍**限值（设备侧 `t=9.9` 写 1，
   EMS `t=10.0` 才读到）→ 改**计数式**（`upper_dead_in >= in_ticks - 3`）。
2. `dis_outside_ticks == 0` 恒红（实际 1）→ 窗外另有 **10 拍是启动期 `state_gated`**
   （非运行态区间收 0）、1 拍是边界延迟 —— 都是**设计内路径**，差分判据必须**显式排除**
   `state_gated` / `hold_last`。

## 18. 缺口 A2：关口功率"同一路数据两个口径"（同日晚间）

### 18.1 缺口本身

`07/src/rtdb/rtdb_device_io.h`：`read_snapshot()`（**算法路径**）用
`p_load - p_pv - p_bat` **推算**关口功率；`read_actuals()`（**记录路径**）
读 `EMS_P_GRID` **电表点**。同一路数据两个口径。

**为什么是安全问题**：两个消费者都是安全约束 ——
**S05 防逆流**（`surplus = p_grid_min - rt.p_grid_kw`）与
**变压器过载**（`|p_grid| + 0.1·p_load`）。真实系统里电表是**唯一权威计量点**，
另三路各有 CT/PT 精度、滤波、通信周期差异，**相减是把误差叠加**而不是抵消；
偏差还随工况漂。现场表现："报表里 100 kW、防逆流却按 137 kW 动作"。

### 18.2 修法（三个适配器 + 一处定义）

- `PlantModel::meter_p_grid()` = **关口功率的唯一定义**；`sample()`（带噪声量测）
  与 `p_grid_actual()`（真值）都从它出 —— 差别只剩"含不含本拍噪声"。
- `RtDbDeviceIO::read_snapshot()` / `MemoryDeviceIO::read_snapshot()` 都改读**电表点**。
- 新增可注入的**电表系统偏差**：`PlantConfig::meter_bias_kw` /
  `DeviceSimConfig::meter_bias_kw` / `MemoryDeviceIO::set_meter_bias_kw()`，
  **默认 0.0 → 既有行为逐位不变**。

### 18.3 ★★ 本次最重要的教训：差点"修了个寂寞"

设备侧发布的 `MEAS.P_GRID` **恰好等于**那个相减式（平衡式本来就成立）
→ 改成"读电表点"后，**所有既有夹具下逐位恒等**，编译/单测/验收全绿，
但**把代码退回去一条断言也不会红**。这与 A1（§17）是同一类陷阱。

**正确顺序**：① 先加**默认 0、可注入**的偏差量把两条路径拉开（可观测差异）；
② 再断言"**跟电表、不跟平衡值**"。
**判据有效性已验证**：把 `read_snapshot()` 退回推算式 → `11/T49` **立刻 6 条红**。

### 18.4 连带发现：T21 的"逐位等价"有一半是 bug 的产物

`MEAS.P_GRID` 原先**只在 `execute()`（拍末）**更新，而负荷/光伏在
`set_environment()`（**拍首**）写入 → 电表读数与其它量测**不在同一时刻**。
改前 `read_snapshot()` 用本拍 load/pv **自己重算**，正好把这个偏差掩盖掉。
→ **等价性本身是被测对象的 bug 维持的。**

改完立刻红 4 处（`d_cmd=75 / d_actual=75 / d_soc=6.46e-05 / d_grid=75`）。
修法：`set_environment()` 末尾同步 `update_grid(get(mem_point::kPBat))` ——
**"一次环境发布 = 同一时刻的一致量测集"**（隐式契约，没人写、但必须守）。
修完 `maxΔcmd=0 maxΔsoc=0 maxΔgrid=0`，**这次是真等价**。
