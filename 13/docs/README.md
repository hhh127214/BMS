## 2. 三件事必须先理解，否则看代码会误判

### 2.1 ★ Modbus 没有品质位 —— "值可信吗"必须由主站**自己合成**

RT_DB 的每个点自带 `data_quality_t`（BAD/GOOD/UNCERTAIN），可信性是**读回来的**。
Modbus 里寄存器就是 16 位裸数据：没有单位、没有时标、没有品质。

后果：**把"读失败"当"读到 0"是最典型的静默失败** —— 0 kW 的负荷、0% 的 SOC
都是看起来完全正常的数值，算法会照常跑，只是跑在一个假世界上。

本模块的纪律：**失败时保留上一次有效值，可信性另行表达**（与 `04/src/device_io.h` 契约①一致）。

### 2.2 ★ 一次快照 = **一组**请求 → 部分成功是常态

一次 Modbus 事务只能读**一段连续地址**。32 个点被规划成 **3 次请求**
（见 §3）。于是"输入寄存器读到了、离散输入超时了"是运行常态。

用**两个独立的位**表达，不能混成一个计数：

| 计数 | 含义 | 现场排查方向 |
|---|---|---|
| `block_fails()` | 分块请求失败 | **通信 / 地址**问题（线、网关、从站地址、超时） |
| `decode_fails()` | 解码失败（字序/NaN/越界） | **映射表配错**（尤其 32 位字序） |

`point_valid(i)` = 所在分块本拍成功 **且** 该点解码成功。两个条件缺一不可。

### 2.3 ★ 32 位浮点字序 —— 现场第一大坑

Modbus 只规定"每寄存器 16 位、大端传输"，**没规定** 32 位量占的两个寄存器谁在前。

- `WordOrder::kHighWordFirst`（"ABCD"）
- `WordOrder::kLowWordFirst`（"CDAB"）

写错的表现**不是"差一点点"，而是数值完全离谱或 NaN**。

★ 映射表里 **`MEAS.P_BAT` 刻意用低字在前**，其余 f32 都用高字在前 ——
这是**故意的区分度**：若全部统一成一种，"把字序写死"的实现也能全绿，
而现场换一台设备就会错。T06 有反向守卫钉住这一点。

## 3. 点表映射（`src/modbus_point_map.h` —— **映射的唯一真相源**）

32 个点按表分三段，**段内地址连续是刻意的**（决定请求次数）：

| 表 | 段 | 地址 | 点数 | 编码 |
|---|---|---|---|---|
| 输入寄存器 IR（FC04，只读） | 量测 | 0..10 | 7 | f32×4 / u16×2 / i16×1 |
| | 空位 | 11 | — | 预留（不挪后面） |
| | 配置 | 12..39 | 14 | f32 ×2 寄存器 |
| 保持寄存器 HR（FC03/06/16，可写） | 指令 | 0..5 | 3 | f32 ×2 寄存器 |
| 离散输入 DI（FC02，只读） | 状态 | 0..7 | 8 | bit |

**读全 32 点 = 3 次请求**。这是**契约**不是实现细节：
T09/T22/`--plan` 都直接断言这个数字，改回"一点一次"立刻变 32
（现场"采一帧要 3 秒"多半就是点表散了）。

四条编译期守卫（`static_assert`）：

| 守卫 | 防的是 |
|---|---|
| `bindings_well_formed()` | 逐点覆盖 / 索引错位 / 编码与表类型不匹配 |
| `segments_consistent()` | 量测·配置·状态被误标可写，或指令点落到只读表 |
| `cmd_points_contiguous()` | **三个指令点地址不连续** → 无法一次 FC16 原子下发 |
| `blocks_cover_all_points()` / `blocks_disjoint()` | 有点没被任何分块覆盖（会恒为默认值）/ 分块重叠 |

### 指令必须**原子下发**

`write_command()` 一次 FC16 写 `(p_bat, p_upper, p_lower)` 共 6 个寄存器。
拆成三次的话，设备可能执行到"**新的功率 + 旧的权限区间**"的中间态，
而那一瞬间新指令可能已经越过旧区间。地址连续由 `cmd_points_contiguous()` 静态保证。

### 3.1 运行期加载（现场点表）—— 两层结构

`kBindings` 是**编译期默认表**（4 条 `static_assert` 只管它）；
`active_map()` 是**运行期活动表**（初值从默认表拷贝，可被 CSV 覆盖）。
不加载任何配置时，两者**逐位相同** —— 默认装配的行为一个字节都没变。

为什么必须有这一层：现场点表**由设备厂家提供**，厂家给的是他自己的地址规划。
为了改一个寄存器地址去重编 C++ 是不可接受的（现场没有编译环境，改完还得重跑测试）。
P3 那条线（IEC104 转发表）已用同款设计。

**CSV 列**（`--dump-map` 导出，或照此手写；支持 `#` 注释行与 Excel 的 UTF-8 BOM）：

```
name,table,address,encoding,word_order,scale,writable,unit,note
```

| 列 | 取值 | 说明 |
|---|---|---|
| `name` | 点名 | 必须与 `ems_point_table.h` 逐字相同。**行序即索引，不许乱序** |
| `table` | IR / HR / DI / CO | 输入寄存器 / 保持寄存器 / 离散输入 / 线圈 |
| `address` | 十进制 0..65535 | 起始地址 |
| `encoding` | f32 / u16 / i16 / bit | 32 位浮点 / 无符号 16 / 有符号 16 / 位 |
| `word_order` | high(ABCD) / low(CDAB) | **仅 f32 有意义**，其余填空即可 |
| `scale` | 数值 | 物理值 = raw / scale；bit 填 0；f32 忽略 |
| `writable` | rw / ro | 只有指令段可以是 rw |
| `unit` / `note` | 任意 | 仅人眼对照，**不参与解析**（不让现场为写备注去翻译我们的术语） |

两条硬纪律：

**① 分块跟着地址重算。** `kReadBlocks` 是编译期常量，但它是从默认表地址推导出来的。
地址一变，固定分块就会"读到了、读的是隔壁寄存器"——静默错。所以加载后由
`derive_read_blocks()` 重新推导（规则：按表分组 → 表内地址升序 → 间隙 ≤ `kMergeGap`(16)
且不超协议上限则合并）。

> 合并阈值不能是 0：默认表 IR 段第 11 号是刻意留的空位，gap = 1。
> 不允许合并的话默认表会被拆成 4 块，"读全 32 点 = 3 次请求"这条契约当场失效。

**② 失败即回退，没有"部分加载"。** 任何一行出错 → **活动表一个字节都不改**，
报出错行号 + 原因，可选地回退到内置默认表。半个点表比没有点表更危险：
一半的点读新地址、一半读旧地址，而**两边都能读出看起来正常的数值**。

校验复用与 `static_assert` **同一套规则**的运行期版本（`validate_map()`）：
位置==索引、点名逐字相等、编码与表类型匹配、缩放规则、段可写性、
指令三点同表且连续、分块覆盖全部点。

### 3.2 随包模板 `docs/point_map_template.csv`

`3.1` 那套机制是**能力**；这份文件是**交付物** —— 真正发给客户去改的起点。

它 = `--dump-map` 的输出 + 一段 `#` 注释头（写清三条硬规矩、九列含义、
以及 `word_order` 是所有现场事故里最常见的那一个坑），数据段与内置默认表
**逐字段一致**，所以客户不必先跑一次程序才能拿到模板。

**为什么单独给它一条判据（T20）**：模板一旦与默认表脱钩（默认表改了地址、
模板没跟着改），客户照它填出来的表会**加载成功、自检通过**，然后读出错误的点。
这是本项目最忌讳的那一类失败 —— 所有信号都是绿的，只有数值是错的。
T20 断言"这份文件能加载，且逐字段等于内置默认表"，与 T17（验 `导出→导入`
这条**机制**）分工不同：机制对而发出的文件是旧的，两件事可以同时成立。

> 模板被删掉/改名也会让 T20 变红（`EXPECT` 而不是 `SKIP`）——
> 因为"发给客户的那个文件"本身就是交付物，缺了它不算环境问题。

### 3.3 ★ 接入参数（`src/device_conn_conf.h` —— 配置通道②）

§3.1 解决的是"点在设备上落哪儿"；**接入参数**（IP / 端口 / 从站号）是另一半，
单独成一份文件：`config/point-map/active.conn`。

**为什么必须有它**（这是接真机时最隐蔽的一类不一致）：

在它之前，接入参数**只存在平台数据库里**。客户在 15/ 界面上填完 `192.168.1.10`，
13/ 与 07/ 却仍然必须靠命令行 `--host 192.168.1.10 --unit 3` 才连得上 —— 于是：

- 界面上写着 `.10`、命令行敲的是 `.1` → **两边都不报错**，现场拿到的数据来自
  一台**没人以为在连**的设备；
- 换个人接手，没人知道该敲哪一串参数（文档里没有，因为它是运行时状态）。

点表通道（§3.1）已经消灭了同一类问题，接入参数却漏在外面 —— 这就是补上它的理由。

**格式**（`key=value`，`#` 注释，UTF-8 可带 BOM，与点表同目录、同一次保存）：

```
format=ems-device-conn/1
device_id=DEV-BMS-01
protocol=modbus_tcp
host=192.168.1.10
port=502
unit_id=3
poll_period_ms=100
timeout_ms=1000
auto_reconnect=1
enabled=1
```

| 键 | 说明 |
|---|---|
| `format` | 文件格式版本。**不认识即拒绝**（宁可报错，也不按自己的理解读） |
| `host` | IPv4 或主机名（白名单：字母数字与 `. _ -`，开头必须是字母数字） |
| `port` / `unit_id` | 1..65535 / **1..247**（0 是广播地址，不能作正常从站） |
| `enabled` | `0` = 该设备未启用。**端侧会拒绝启动**，见下 |
| `saved_at` / `username` | 元信息，只给人看，缺了不影响 |

**三条纪律**（与点表加载逐条对齐，现场行为才可预期）：

**① 文件不存在 ≠ 错误，但绝不编默认值。** "现场还没配"是正常状态，调用方按
自己的方式提示（probe 报"没有接入参数"并退回内置默认 `127.0.0.1`，07/ 报
"要么给 `--host` 要么先在界面上配置"）。关键是**不编一个 IP 出来** ——
编出来，程序就会真的去连它，而屏幕上一切正常。

**② 文件存在但非法 = 硬失败。** 不回退。静默回退会让「平台把参数写错了」与
「平台还没写参数」在现场表现一模一样，而前者会让人以为配置已生效。

**③ 未知键 = 硬失败。** 拼错一个键名（`hots=` / `prot=`）若被忽略，程序会拿
默认值（`502` / 从站 `1`）去连 —— 而屏幕上一切正常。所以宁可当场拒绝。

**`enabled=0` 的语义**：加载**成功**（文件合法），但它是"这台先别接"的明确意图。
probe 与 07/ 各自给出恰当的处置（都拒绝自动连接，提示改用 `--host` 显式指定），
而不是在解析层一刀切 —— 解析层只负责如实报告事实。

**取值优先级**（probe 与 07/ 一致）：

```
命令行 --host/--port/--unit  >  约定路径的 active.conn  >  内置默认（仅 probe：127.0.0.1）
```

命令行优先是刻意的：现场临时核对一台设备，不该被平台配置挡住。

> **目录约定只有一处**：`active.conn` 与 `active.csv` 同在
> `<项目根>/config/point-map/`（环境变量 `EMS_POINT_MAP_DIR` 同时覆盖两者）。
> 本文件的 `default_device_conn_path()` 直接复用 `modbus::default_point_map_dir()`，
> **不另立一套** —— 两侧分叉等于"平台写 A、端侧读 B"，配置永远不生效而两边各自成功。
> 判据 T38 专门钉这一条。

**落盘方是 14/**（`14/src/connconf.py`）：界面上点"保存接入参数"时，与点表
**同一次保存、同生共死**地写出这个文件（原子写：先写临时文件再 `os.replace`，
避免端侧读到写了一半的半份配置）。把地址清空会**删掉**该文件 ——
留一个旧地址会让端侧下一拍去连一台已经换掉的设备。

## 4. 怎么跑

### 4.1 构建

```bat
13\scripts\build.bat          :: → build\modbus_probe.exe（现场点表核对工具）
13\scripts\build_test.bat     :: → 三层测试，编译 + 运行
```

也可以从根目录跑（已挂在 `scripts/build_all.bat` 第 **30 / 31** 步）：

```bat
scripts\build_all.bat              :: 全量 31 步
scripts\build_all.bat --no-test    :: 跳过所有测试
```

### 4.2 起设备替身（Python 从站）

```bat
python -m venv .venv
.venv\Scripts\pip install -r 13\sim\requirements.txt
13\scripts\run_sim.bat --load 380 --pv 150 --bias 40
```

常用参数（都是**现场工况**的旋钮，用来复现问题）：

| 参数 | 用途 |
|---|---|
| `--load / --pv` | 负荷 / 光伏出力 |
| `--bias` | **电表系统偏差**。非 0 用于验证主站读的是电表口径（见 §5） |
| `--soc0 / --soh / --ambient-c` | 初始 SOC / SOH / 环境温度 |
| `--bms-chg-forbid` / `--bms-dis-forbid` | 模拟 BMS 上报禁充 / 禁放 |
| `--pcs-fault` / `--offline` | 模拟 PCS 故障 / 设备离线 |
| `--tau-s / --ramp-kw-s` | 一阶惯性时间常数 / 变化率上限（与 `07/` 同式） |
| `--self-check` | 打印 32 点对照表（**人眼**核对用） |
| `--dump-tsv` | 打印 TSV（**机器**比对用，给 T40） |
| `--check-pymodbus` | 只探测依赖是否可用（给构建脚本决定 skip/fail） |

### 4.3 读真机 / 读模拟器

```bat
13\build\modbus_probe.exe --plan                  :: 只打印分块读计划（不发报文）
13\build\modbus_probe.exe --port 15020            :: 读一遍 32 点
13\build\modbus_probe.exe --port 15020 --repeat 10 --interval 1
13\build\modbus_probe.exe --host 192.168.1.10 --port 502 --unit 3
13\build\modbus_probe.exe                          :: ★ 不给 --host：读约定的接入参数文件
13\build\modbus_probe.exe --dump-conn              :: 看看"现在到底在跟谁说话"（不发报文）
13\build\modbus_probe.exe --port 15020 --set-power -60 --verbose
13\build\modbus_probe.exe --dump-map              :: 导出当前生效点表为 CSV（可直接当模板）
13\build\modbus_probe.exe --load-map 点表.csv --plan
13\build\modbus_probe.exe --port 15020 --load-map 点表.csv
```

★ **不给 `--host` 时**，工具按 §3.3 读 `config/point-map/active.conn`（平台在界面上
保存接入参数时写出）。输出的「**接入参数**」一行会如实报出来源，三种情形都明说：

```
接入参数   : 约定路径 ← ...\config\point-map\active.conn
             设备号 DEV-BMS-01  协议 modbus_tcp  地址 192.168.1.10:15020  从站 3 ...
接入参数   : 约定路径下没有 active.conn —— 用内置默认 127.0.0.1:502
接入参数   : 命令行指定（接入参数文件已读取但未采用）
```

排障第一步永远是"我现在到底在跟谁说话"——**这一行就是回答**。
命令行给过 `--host` 时以命令行为准（现场临时核对一台设备，不该被平台配置挡住）。

**现场点表三步走**（这是 §3.1 那套机制的日常用法）：

```bat
:: 1. 先从内置表导出模板
13\build\modbus_probe.exe --dump-map > 点表.csv
:: 2. 用 Excel 照厂家手册改地址 / 字序 / 缩放（unit/note 列可随手写，不参与解析）
:: 3. 加载并核对 —— 盯最右的 ok 列
13\build\modbus_probe.exe --host 192.168.1.10 --port 502 --unit 3 --load-map 点表.csv
```

输出的第二行固定打印「**点表来源**」：加载过就显示 CSV 路径，否则显示"内置默认表"。
排障时"现在跑的到底是哪张表"永远是第一个要回答的问题。

★ 加载失败时工具**直接停下**（退出码 2）并打印出错行号，**不会**带着默认表继续跑 ——
否则屏幕上一片正常，用的却是内置表，而那正是最容易误判的一种"看起来在工作"。
接入参数文件非法、或平台把该设备标为 `enabled=0` 时，同样**直接停下**（退出码 2）。

`ok` 列是**最重要的一列**：`--` 表示该点本拍不可信。
记住 §2.1 —— 值为 0 且 `ok=false` 与"真的是 0"，在协议上完全一样，
**只有这一列能把它们分开**。

## 5. ★ 关口功率口径（跨语言可复核的证据）

Python 从站的电表读数 = 平衡值 + `--bias`：

```
p_grid = (p_load + standby) - p_pv - p_bat + meter_bias
```

主站若在本地重算 `(load + standby - pv - p_bat)`，会得到比电表**小 bias** 的值。
两个写法在 `bias = 0` 时**逐位相等** —— 所以必须用非 0 bias 把两者拉开。

实测（`--bias 40`，读两遍，第二遍已下发 -60 kW）：

| 遍 | `p_bat` | `p_grid` | 校验 |
|---|---|---|---|
| 1 | 0.00 | 272.00 | `380+2-150-0+40 = 272` ✓ |
| 2 | -57.41 | 329.41 | `272 - (-57.41) = 329.41` ✓ 且模型正在跟踪指令 |

T42 直接断言 `p_grid - 本地重算 == 40`，并带**反向守卫**
（`|差| > 30`）—— 没有反向守卫，两个口径碰巧相等时断言也会过。

这一层立刻抓出了 6 个真问题（见 §8），其中 3 个是前两层**照不出来**的。

### 环境缺失时的行为（**skip 而非 fail**，但必须显式）

`test_modbus_bridge.exe` 做**两级**环境探测：

| 级别 | 探测 | 失败含义 | 处置 |
|---|---|---|---|
| 1 | `--dump-tsv`（不 import pymodbus） | 没有 python / 脚本路径不对 | SKIP |
| 2 | `--check-pymodbus` | 有 python 但**没装 pymodbus** | SKIP + 安装指引 |
| — | 两级都过 | 起不了服务 = **真缺陷** | FAIL |

★ 第 2 级不能省：`--dump-tsv` 不需要 pymodbus，所以"没装 pymodbus"
会通过第 1 级，然后在起服务时失败 —— 被报成**代码缺陷**。
这个区分不做，构建脚本就会在没装 pymodbus 的机器上**永久假红**。

解释器定位顺序：`EMS_PYTHON` → `13/.venv/Scripts/python.exe` → PATH 上的 `python`。
（`build_test.bat` 与 C++ 侧的 `which_python()` 是同一套顺序。）

### ★ 但"测试层诚实"只做了一半 —— 上层必须也承认自己没跑

第一版只在**测试层**做对了（打 `SKIPPED=7`、退出码 0），跑完整 `build_all.bat` 才发现
`build_test.bat` 的收尾行**仍然印 `[OK] 13\ Modbus 三层测试全部通过`** ——
**最终结论行是假的**。这正是本项目最忌讳的「静默降级」：把"没验"写成了"验过"。

三处修法（完整复盘见 `CHANGES.md` §27.12）：

1. 桥接测试**总是**打印 `SKIPPED=n`（哪怕是 0）—— 让"跑了"有**正面证据**；
   并另落一行**纯 ASCII** 的 `build/bridge_status.txt`（`PASS=… FAIL=… SKIPPED=…`）。
2. `build_test.bat` 先 `del` 旧状态文件 → 跑测试 → `findstr /C:"SKIPPED=0"` 取判定 →
   收尾行**据实**二选一：`[OK] 三层（813 条）` / `[SKIP] 前两层（597+133），跨语言层未运行，
   本次 13\ 只贡献 735 条`。文件不存在也按「未跑」处理 —— **宁可多报 SKIP，不可漏报**。
3. 为什么读**文件**而不是 grep 输出：`build_all.log` 是**混合编码**的
   （`.bat` 的 `echo` 走 CP936、C++ 的 `printf` 走 UTF-8），对中文做 grep 不稳。

> ★ 通用纪律：**凡是"允许不跑"的测试层，都必须有一个"跑了没有"的显式信号，
> 一路传到最外层结论行。** 只让测试层自己诚实是不够的 ——
> 只要上层给出一个相反的结论行，读结论的人就只会记住那一行。

### 判据有效性反证（项目最硬纪律，本模块做了 **8 次**）

| # | 退回/破坏的写法 | 结果 | 抓它的测试 |
|---|---|---|---|
| 1 | Python 侧 `p_grid` 去掉 `+ meter_bias` | **3 条红** | T42 |
| 2 | Python 点表 `IR_P_GRID` 6 → 7 | **3 条红**（T40 精确定位到第 3 行并并排打两侧字段） | T40 |
| 3 | Python 侧 `read_command` 恒返回 None（不消费指令） | **4 条红** | T43 / T44 |
| 4 | `simdata` 交换 DI↔IR | pymodbus 构造时 `TypeError` 直接拒绝 | ★ **非缺陷**，见下 |
| 5 | `simdata` 交换 CO↔DI（同为 BITS） | 仍 83/0 全绿 | ★ **非缺陷**，见下 |
| 6 | `binding_for_index()` 退回读编译期 `kBindings`（运行期表被旁路） | **14 条红** | T17~T19 |
| 7 | `derive_read_blocks()` 不重算，沿用编译期分块 | **8 条红**（`active_block_count()=3 vs 4`、解码 `v=0.55 vs 55.0`） | T16 / T18 |
| 8 | 随包模板里 `MEAS.P_PV` 的 IR 地址 2 → 101（**仍合法、仍能加载**） | **2 条红**（打印 `模板分块数 4 != 默认 3`） | T20 |

> 反证 8 是最能说明问题的一条：那份表 `--load-map` **加载成功、自检通过**，
> 唯一的异常是它已经不等于内置默认表了。没有 T20，"客户拿到的模板是旧版"
> 这件事在整条测试链路上**不留任何痕迹**。

★ 反证 4/5 的意义：**它们证明我在注释里写错了一句**。原注释声称
"元组顺序写反会让四张表整体错位、只能靠跨语言对账抓"。实测结论是：
① 跨类型写反由 pymodbus 的类型检查当场拒绝，不静默；
② 同类型写反**没有影响** —— 表身份由**位置**决定，而读写都走同一功能码入口，
换掉某个位置上的对象不改变对外语义。
真正的风险是 **C++ 侧 `Table` 枚举与标准功能码的对应**写错，那才"读错表"且协议层完全合法，
由 T40 + T41 守着。**注释已按实测结论改正。**
（这就是"注释声称的行为必须与代码实际行为一致"那条纪律的又一次实战。）

跨语言层需要外部 Python + pymodbus。因此本模块的贡献有**两个合法值**：

| 条件 | 13/ 贡献 | `build_test.bat` 收尾行 | `bridge_status.txt` |
|---|---|---|---|
| **开箱默认**（仓库里没有装了 pymodbus 的 Python） | **735**（597+133+**5**） | `[SKIP] … 跨语言层未运行` | `PASS=5 FAIL=0 SKIPPED=7` |

"没装 pymodbus ⇒ 该层贡献 0" 是一个很容易犯的推断，实测值见上表

对中文做 grep 不稳。

### 8.3 与 pymodbus 版本绑定的硬事实

`13/sim/modbus_slave.py` 文件头有完整记录。三条最容易踩的：

1. **不要走 `ModbusDeviceContext` + `ModbusSequentialDataBlock` 老路**：
   3.15 里 `ModbusDeviceContext.__init__` 对 data block 做 `deepcopy`，
   构造后再改 `ir.simdata[...]` **服务端看不见**，而且**不报错**（主站永远读到 0）。
   正确做法：`pymodbus.simulator` 的 `SimData/SimDevice` + `pymodbus.server.ModbusTcpServer`。
2. **`SimData.count` 对 BITS 是乘数**：`count=64` 配 64 个 bool 会展开成 4096 位。传 1。
3. **更新寄存器只有一个公开入口**：`server.async_setValues(unit, fc, addr, values)`，
   `fc` 是**标准功能码**（1=CO 2=DI 3=HR 4=IR）。所以脚本必须自己持有
   `ModbusTcpServer` 实例 —— `StartAsyncTcpServer()` 是 fire-and-forget，拿不到句柄。

| `05/` | 消费 `read_limits()` 的输出的那两个 bool（BMS 禁充放）折进安全区间 |
| `07/` | 实时闭环；`ModbusDeviceIO` 与 `SimDeviceIO` 可直接互换装配 |
| `07/src/rtdb/ems_point_table.h` | **点表真相源（40 点）**。本模块只绑设备侧前 32 点（EXT 区不经设备总线），点名与索引直接取自它，不另抄一份 |
| `11/` | 跨进程联调（RT_DB 路线）。本模块是"跨**网络**"那条路，与它并列 |
| `12/` | 验收；本模块的断言总数进全量基线 |
| `P3/` | IEC104 从站网关（对上）。本模块是**对下**（对设备）。两条方向相反，都不得绕过 `05/` |

★ **共同纪律**：无论数据从哪来（IEC104 遥控 / Modbus 写 / RT_DB 写），
**调度侧的任何设定都不得绕过 `05/` 安全约束引擎**。本模块的 `write_command()`
只接受 `PowerCommand`（已含 `p_upper/p_lower`），不提供"只写功率"的接口 ——
这就是在类型上表达这条纪律。
